## ส่วนที่ 2 — S05 lifecycle commands (`@gm/domain`, pure)

`lifecycle.ts` รับ state + `now` + actor แล้วคืน state ใหม่ + history event หนึ่งรายการ (หรือโยน `LifecycleRejected` พร้อม `code`) ไม่อ่านเวลาเครื่อง ไม่เขียน Firestore; idempotency/`expected_revision` อยู่ S08/A03

| Command | ใคร | จาก → ไป | ผล |
|---|---|---|---|
| `acceptRequest` | GM | `queued` → `in_progress` | `assigneeId` = GM ผู้กด, `lastUpdatedAt` = now |
| `completeRequest` | GM + สรุปผล | `in_progress` → `completed` | `completionCycleId` +1, `completedAt`; **มี `requesterId`** → `autoCloseDueAt` = `autoCloseDue(completedAt, ปฏิทิน)` จาก S03 + copy `confirmationCalendarSnapshot`; **ไม่มี** (`gm_task`/ชื่อข้อความ) → `closedAt` = now, `closureKind` `gm_closed` ทันที; `lastUpdatedAt` = now |
| `confirmCompletion` | `requesterId` เท่านั้น | `completed` รอยืนยัน | `closedAt`, `closureKind` `requester_confirmed`; เก็บ due เดิม; ไม่แตะ `lastUpdatedAt` |
| `reportNotResolved` | `requesterId` เท่านั้น + เหตุผล | `completed` รอยืนยัน → `in_progress` | ล้าง `completedAt`/`autoCloseDueAt`/snapshot ของรอบนั้น (ค่าเก่าอยู่ใน history event) คง `completionCycleId`/assignee; ไม่แตะ `lastUpdatedAt` |
| `autoCloseRequest` | scheduler (`system`) | `completed` รอยืนยัน | ตรวจ source/`completed`/`closedAt` ว่าง/cycle ตรง/ถึง due ครบ; ผ่าน → `closedAt` = เวลาปิดจริง, `closureKind` `auto_closed` เก็บ due เดิม; ไม่ผ่าน → `applied: false` + `skipReason` ไม่ throw; ไม่แตะ `lastUpdatedAt` |
| `cancelRequest` | GM + เหตุผล | `queued`/`in_progress`/`waiting` → `cancelled` | `cancelledAt`, `lastUpdatedAt` = now |
| `reopenRequest` | GM + เหตุผล | `completed` → `in_progress`; `cancelled` → `queued` | ล้าง field ของรอบปิด/ยกเลิก คง `completionCycleId`; `lastUpdatedAt` = now |

- ทุกคำสั่งเป็น generic `<S extends LifecycleState>` คืน object เดิมทั้งก้อนโดยแก้เฉพาะ field lifecycle จึงไม่ล้าง `slaBreachedAt` หรือ field อื่น (US-09); `completionCycleId` ไม่ reset; history เป็นของ caller ที่ append event
- field ที่ล้างจะหายจาก object (ไม่ใช่ `undefined`) ให้ map ลง Firestore ได้ตรง
- `source = trello` → `READ_ONLY_SOURCE` ทุกคำสั่ง GM และ auto-close ข้าม (`read_only_source`)
- ยืนยัน/แจ้งยังไม่เรียบร้อย: ไม่ใช่ผู้ขอ (watcher, related, GM) → `REQUESTER_ONLY`; ปิดแล้ว → `ALREADY_CLOSED`; ไม่ใช่ `completed` → `NOT_AWAITING_CONFIRMATION`; รอบเก่า → `STALE_COMPLETION_CYCLE`
- รหัสอื่น: `GM_ONLY`, `INVALID_TRANSITION`, `REASON_REQUIRED`, `RESULT_SUMMARY_REQUIRED`, `CONFIRMATION_CALENDAR_REQUIRED`
- `isGm` ใน `request-creation.ts` export ภายในแพ็กเกจเพื่อใช้ร่วม; `@gm/domain` เพิ่ม dependency `@gm/time` (ผ่าน purity test ที่อนุญาตเฉพาะ `@gm/time`)

## คำถามค้าง (ไม่เดา — ทำแบบแคบที่สุดไว้ก่อน)

1. **กดเสร็จจากสถานะอื่นนอกจาก `in_progress`** — F04 เขียนว่าผังเป็น “เส้นทางหลัก ไม่ใช่การจำกัด” แต่ไม่ระบุว่า `queued` หรือ `waiting` → `completed` ตรงๆ ได้หรือไม่ ตอนนี้อนุญาตเฉพาะ `in_progress` (ถ้าจากรอผู้อื่นได้ ต้องปิด waiting interval ซึ่งเป็นงาน S06)
2. **ยกเลิกงานที่ `completed` รอยืนยัน** — ผังไม่มีเส้น `completed → cancelled` ตอนนี้ปฏิเสธ (`INVALID_TRANSITION`) ให้ GM เปิดกลับก่อน ถูกต้องหรือไม่
3. **ผู้ขอแจ้ง “ยังไม่เรียบร้อย” ควรอัปเดต `last_updated_at` หรือไม่** — spec บอกเฉพาะว่า GM progress อัปเดต และ scheduler ห้ามอัปเดต ตอนนี้ไม่อัปเดต ผลคือถ้า GM ไม่ได้แตะงานนานกว่า 3 วันทำการ งานจะขึ้น stale ทันทีที่กลับเป็น `in_progress`
4. **เปิดกลับงานที่ยกเลิก (`cancelled → queued`) คงผู้รับผิดชอบเดิมหรือไม่** — ตอนนี้คง `assigneeId` เดิม; กฎ “`queued` unassigned” และกฎลาอยู่ S07
5. **รับเรื่องงานที่มอบหมายให้ GM คนอื่นอยู่แล้ว** — ตอนนี้ `accept` ตั้งผู้กดเป็น assignee เสมอ; ควรห้าม/ต้องยืนยันการรับแทน หรือไม่ และการตรวจ effective leave ตอนรับเรื่อง (§6.6) อยู่ S07
6. **ปลดธงลับโดย GM Admin (D-S04-4/C6)** — คำสั่งปลดธงพร้อมเหตุผลยังไม่มีใน task ใดชัดเจน และ GM เปิดธงเองโดยไม่ใช่เรื่องสัญญา/บุคคลยังไม่มีค่า `sensitivity_reason` (มีเฉพาะ `contract`/`personnel`) ต้องการค่าใหม่ เช่น `gm_marked` หรือไม่ (ต้องได้คำตอบก่อน A01)
