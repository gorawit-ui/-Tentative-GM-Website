## Decisions ที่ปิดแล้ว

บันทึกเหตุผลใน [DECISIONS](../spec/DECISIONS.md):

- `D-S01-1`: Persisted shape `CalendarSnapshotDocument` อยู่ `packages/contracts`: `timezone`, `open_weekdays`, `holidays`, `hash`, `source`; calculation type ใช้ camelCase ภายในได้; ISO weekdays 1–7 คงเดิม
- `D-S01-2`: `business_days` เป็น canonical ตาม C8; `business_day` ไม่รับเป็น alias
- `D-S01-3`: duration 0 ยังคง invalid; elapsed ที่วัดได้ 0 ไม่ใช่ configured duration
- `D-S01-4`: configured duration จำนวนเต็มวันบวกเท่านั้น `business_days`/`continuous_24h`; raw milliseconds สำหรับ elapsed/interval ไม่ถูกปัดเป็นวัน และไม่ใช่ hours policy unit
- `D-S01-5`: validation รับเฉพาะ `Asia/Bangkok`; ไม่ขยาย Phase 1 ไป DST/zone อื่น
- `D-S01-6`: holiday Gregorian year 2000–2100 inclusive; RangeError ชี้ว่าน่าจะกรอกเป็น พ.ศ.; ไม่แปลงเอง การแปลง/preview/confirm อยู่ Admin A11 และ import B20–B22 ตาม R5

`hash` และ `source` เป็น metadata ที่ caller จะจัดให้ตอน snapshot creation ไม่เพิ่ม Firestore SDK/dependency หรืออ่าน calendar สดใน time package `CalendarSnapshotDocument` เป็น persisted contract; ยังไม่ทำ serializer/writes ใน session นี้

## API ของ S02 — pure calculation inputs ไม่ใช่ Firestore document shape

| API | ความหมาย |
|---|---|
| `mergeIntervals(intervals)` | union ของ closed half-open ranges `[start,end)`; sort copy, merge overlapping/duplicate/contained/touching ranges, drop empty ranges; input ไม่เปลี่ยน |
| `effectiveWaitingEnd(interval, now)` | min ของ `now`, `respondedAt`, `exitedAt`; ตรวจ timestamp และ chronology; ไม่มี terminal ใช้ now |
| `waitingElapsed(interval, now, unit, calendar)` | raw party wait หรือ business wait ใช้ effective end เดียวกัน; `business_days` เรียก `businessDuration` จาก S01 |
| `slaElapsed(request, now)` | elapsed ของ clock minus union ของ effective waits ที่ clip กับ window; `business_days` เรียก S01, `continuous_24h` นับทุกเวลา; ไม่เปลี่ยน status/history/stale |

`WaitingInterval`: `startedAt`, optional `respondedAt`, optional `exitedAt`. `SlaClock`: `startedAt`, optional `stoppedAt`, `unit`, immutable `calendarSnapshot`, `waitingIntervals`. `stoppedAt` เป็น milestone stop ที่ caller เลือกแล้ว ไม่อ่าน/เดา status ภายใน calculator ค่าส่งเข้าทุก instant เป็น UTC epoch milliseconds เช่น S01; absent optional fields ใช้ `undefined` หลัง boundary mapping

Future/old intervals ไม่หักเวลานอกช่วง SLA; invalid history โยน RangeError ไม่แอบแก้ลำดับ เมื่อคน A เปลี่ยนเป็น B caller ปิดช่วง A และเปิดช่วง B ไม่แก้ช่วงเดิม คำตอบจาก interval เก่าต้องถูกปฏิเสธใน domain/API S06 ซึ่งยังไม่ได้ทำที่นี่
