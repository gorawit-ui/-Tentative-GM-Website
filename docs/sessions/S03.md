## สิ่งที่ส่งมอบ (`@gm/time`)

| ฟังก์ชัน | กติกา |
|---|---|
| `staleState(lastUpdatedAt, now, calendar)` | `{ elapsed (raw), thresholdAt, stale }`; stale เมื่อ elapsed **มากกว่า** 3 วันทำการ (Part 6 “เกิน”); ครบ 3 วันทำการพอดียังไม่ stale |
| `autoCloseDue(completedAt, calendar)` | `completed_at` + 3 วันทำการ (C5) |
| `isAutoCloseDue(completedAt, now, calendar)` | true เมื่อสะสม **อย่างน้อย** 3 วันทำการ (Part 6 “ครบ”) |
| `formatBusinessDuration(raw, context)` | context `waiting` → “ไม่ถึง 1 วันทำการ” / “X วันทำการ”; `last_update` → “อัปเดตล่าสุดไม่ถึง 1 วันทำการที่แล้ว” / “อัปเดตล่าสุด X วันทำการที่แล้ว”; `gm_stale` → “ไม่ขยับ X วันทำการ · ถึงเวลาติดตาม” (ใช้ได้เฉพาะ raw > 3 วันทำการ); X ปัดลงเป็นจำนวนเต็ม (F4) |
| `snapshotCalendar(live)` | ตรวจความถูกต้องแล้ว copy เป็น object แช่แข็ง (deep freeze) weekdays/holidays เรียงและตัดซ้ำ แก้ live calendar ภายหลังไม่กระทบ snapshot |

การกรองสถานะที่ stale ได้ (`queued`/`in_progress`/`waiting`), เหตุการณ์ที่ reset `last_updated_at`, และการเลือกว่างานไหน auto-close ได้ (มี `requester`, ไม่ใช่ข้อความเปิดแทน) อยู่ใน `@gm/domain` (S04–S06) ตาม CLAUDE.md “status/ACL/lifecycle อยู่ packages/domain” — `@gm/time` ทำเฉพาะเลขเวลา

## คำถามค้าง (ไม่เดา)

1. **“วันนี้”** — P7-UX-01 ให้ใช้ “ไม่ถึง 1 วันทำการ” หรือ “วันนี้” ตามวันที่จริง และ Part 6 ให้ “วันนี้” เฉพาะ context ที่วันที่เกิดวันนี้จริง แต่ไม่ระบุว่าเป็นข้อความบนหน้าจอใด `formatBusinessDuration` รับแค่ระยะเวลา จึงยังไม่สร้างข้อความ “วันนี้” — ต้องการให้ใช้ที่ข้อความใด (เช่น วันที่สร้าง/วันที่อัปเดต) จะทำใน UI task ที่เกี่ยวข้อง
2. **ทศนิยมหรือจำนวนเต็ม** — U4 ยกตัวอย่าง “ทศนิยมหนึ่งตำแหน่ง” แต่ F4 (ใหม่กว่า และอยู่ลำดับสูงกว่า U1–U5 ใน INDEX) ให้ “จำนวนเต็มปัดลง” จึงใช้จำนวนเต็มปัดลง ยืนยันว่าไม่ต้องมีทศนิยมที่ใดเลย
3. **ป้าย GM ที่ขอบเขต** — stale เริ่มเมื่อ “เกิน” 3 วันทำการ แต่ตัวเลขที่แสดงปัดลง ดังนั้นช่วงแรกที่ stale จะแสดง “ไม่ขยับ 3 วันทำการ · ถึงเวลาติดตาม” ยอมรับได้ไหม
4. **Hash/source ของ snapshot** — Part 6 ให้ snapshot เก็บ “hash/`source` reference” แต่ไม่ระบุ algorithm หรือรูปแบบ `snapshotCalendar` จึงคืนสำเนาที่ normalize แล้ว (เรียง/ตัดซ้ำ) ยังไม่มี hash; ให้ S04/B01 กำหนดพร้อม field ที่เก็บใน Firestore
5. คำถามค้างจาก [S01](S01.md) (schema snapshot, `business_days`/`business_day`, duration 0, หน่วยชั่วโมง, โซน DST, วันหยุด พ.ศ.) ยังไม่ได้คำตอบ
