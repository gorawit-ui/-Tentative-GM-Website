## ส่วนที่ 2 — A12

### API (ต้อง login บัญชีบริษัทที่ใช้งานอยู่; ทุก role แจ้งซ่อมได้ D-S04-6; ก่อน login ไม่ตอบอะไร)

- `GET /api/repair/options` → สถานที่ที่เปิด (ลำดับของ Admin รวมที่ Admin เพิ่มใหม่), บริเวณที่เปิดของสถานที่ที่เปิด, อาการ 14 รายการตาม brief; ยังไม่พร้อม → 503 `PLACES_NOT_SET_UP` / `ROUTING_NOT_CONFIGURED` / `CALENDAR_NOT_CONFIGURED` (FU-21, D-A01-2)
- `GET /api/repair/qr/:qr_id` → `ok` (location_id, area_id) / `not_found` (รวมรูปแบบรหัสผิด) / `qr_inactive` / `location_inactive` / `area_inactive` (+ location_id ถ้าสถานที่ยังเปิด) — ไม่เขียนอะไร ไม่ออกเลขงาน
- **FU-19**: `firestoreMaintenanceCatalog` แทน `CATALOG_NOT_READY` ใน `main.ts` — อ่านใน transaction ของคำสั่งสร้าง: สถานที่เปิด, บริเวณเปิดและเป็นของสถานที่นั้น, อาการในรายการ → 422 `LOCATION_UNAVAILABLE` / `AREA_UNAVAILABLE` / `SYMPTOM_UNKNOWN`; ชื่องาน U2 จาก label ปัจจุบัน
- อาการ (`@gm/domain` `MAINTENANCE_SYMPTOMS`): `aircon` แอร์, `light_bulb` หลอดไฟ, `power_outage` ไฟดับ, `internet` อินเทอร์เน็ต, `restroom` ห้องน้ำ, `sink` ซิงค์, `elevator` ลิฟท์, `cctv` กล้องวงจรปิด, `air_purifier` เครื่องฟอกอากาศ, `printer` เครื่องปริ้นท์, `desk` โต๊ะ/โต๊ะแพ็ค, `shelf` Shelf, `electrical_panel` ตู้ไฟ, `other` อื่นๆ

### หน้าจอ

- **สแกน QR ก่อน login**: `/q/:qr_id` → `/login?next=/q/…` หน้า login เดิม + “เข้าสู่ระบบเพื่อแจ้งซ่อมจากจุดที่สแกน” + กล่อง “ไม่มีบัญชีบริษัท? แจ้งทีม GM” (A1.3); ไม่แสดง/ไม่ถามข้อมูลสถานที่ก่อน login; login แล้วกลับ `/q/…` (มี session อยู่แล้วข้าม login)
- **QR ใช้ได้**: เลือกสถานที่+บริเวณให้ เริ่ม “ขั้น 3 จาก 4” พร้อมกรอบ “เลือกจาก QR ให้แล้ว · WH300 · ห้องแพ็คชั้น 1” และ “ไม่ใช่ที่นี่? เปลี่ยนสถานที่/บริเวณ”
- **QR ใช้ไม่ได้**: แจ้งเหตุ (role=alert) “ไม่พบ QR นี้…” / “QR นี้ถูกปิดใช้งานแล้ว…” / “สถานที่ของ QR นี้ปิดใช้งานแล้ว…” → ขั้น 1 ไม่เติมอะไร; “บริเวณของ QR นี้ปิดใช้งานแล้ว…” → คงสถานที่ไว้ เริ่มขั้น 2 (บริเวณที่ปิดไม่อยู่ในตัวเลือก)
- **ขั้น 1–3**: stepper 4 ขั้น + “ขั้น N จาก 4”, สถานที่/บริเวณที่เลือกแสดงทุกขั้น (F01); ปุ่มตัวเลือก 2 คอลัมน์ (desktop 3) `aria-pressed`; เปลี่ยนสถานที่ → เลือกบริเวณใหม่; บริเวณมี “ไม่ระบุ” + “ไม่พบบริเวณ? เลือก “ไม่ระบุ” แล้วบอกจุดที่เกิดปัญหาในรายละเอียด” (สถานที่ไม่มีบริเวณ → “ไม่ระบุ” อย่างเดียว); อาการ 14 รายการ; ไม่เลือกแล้วกด “ถัดไป” → บอกให้เลือก; เลือกอาการแล้วแสดง “ชื่อบนบอร์ด · สร้างให้อัตโนมัติ” (U2 ด้วย `repairTitlePreview` ฟังก์ชันเดียวกับ server) เปลี่ยนตามเมื่อย้อนกลับแก้
- **ขั้น 4**: แสดงชื่อที่จะใช้ + “รายละเอียด รูป และการส่งเรื่องเปิดใช้ในรุ่นถัดไป” (A14) — ยังส่งงานจากหน้านี้ไม่ได้
- **ยังตั้งค่าไม่ครบ (FU-21)**: “ระบบแจ้งซ่อมยังตั้งค่าไม่ครบ ยังส่งเรื่องจากหน้านี้ไม่ได้” + เหตุ + กล่องติดต่อทีม GM (ช่องทางเดียวกับหน้า login) ไม่แสดงฟอร์มเปล่า
- **F6**: ไม่มี bottom nav ทั้งฟอร์ม; action bar 64 px + safe area (มือถือ fixed, `scroll-margin-bottom` ให้ปุ่มที่ถูก focus ไม่จมใต้แถบ); 360×640 เห็นปุ่มอาการ ≥ 4 โดยไม่ต้องเลื่อน; desktop ฟอร์ม ≤ 720 px แถบปุ่มในเนื้อหา
- ไม่มี horizontal scroll 4 ขนาด, ปุ่ม ≥ 44 px (ทุกเคส e2e)

## คำถามค้าง (ทำตามที่ระบุไว้ก่อน รอยืนยัน)

1. **Q-A12-1 งาน `waiting` ของ GM ที่ถูกปิดบัญชี** — ล้างผู้รับผิดชอบแต่ยังรอฝ่ายเดิมอยู่ (ไม่ปิดช่วงรอ ไม่กลับเป็น `queued`) — ใช้ได้ไหม หรือให้กลับเป็นรอคิว
2. **Q-A12-2 ลด role GM ที่มีงานค้าง** (ไม่ได้ปิดบัญชี) — ตอนนี้งานยังอยู่กับคนนั้น (D-A10-2 พูดถึงการปิดบัญชีเท่านั้น) — ต้องปล่อยงานแบบเดียวกันไหม
3. **Q-A12-3 รหัสอาการ** — ตั้งไว้ในโค้ดตามรายการ brief (ด้านบน) Admin แก้ไม่ได้ — ยืนยันรหัส และต้องการให้ Admin เพิ่ม/ปิดอาการเองในรุ่นถัดไปไหม (SLA ด่าน B อ้าง “ไฟดับ / อินเทอร์เน็ต”)
4. **Q-A12-4 ข้อความ QR หลัง login** — บอกแยก ไม่พบ / ปิดใช้งาน / สถานที่ปิด / บริเวณปิด (ก่อน login ไม่บอกอะไรเลย ตาม FU-43) — ใช้ได้ไหม
5. **Q-A12-5 ร่างฟอร์ม** — Part 3 §0.2 ให้พักร่างเฉพาะ session บนอุปกรณ์ เมื่อออกจากฟอร์มตอนนี้ค่าหาย — ทำพร้อม A14 (ขั้น 4) ไหม
