## ส่วนที่ 2 — A02

### ภาพรวม

```text
API create (transaction) ── outbox pending ──► [Cloud Tasks: FU-20 รอ P7-INFRA-01] ──► POST /internal/tasks/outbox ─┐
                                   ▲                                                                                  ├─► dispatchOutbox
Scheduler 1 job */15 Asia/Bangkok ─┴─► POST /internal/tick ─► lease scheduled_work/tick ─► outbox recovery ───────────┘
   (dev: npm run tick:local)                                                           └─► scheduled_work jobs ─► runJob
```

### กติกาเวลา / สถานะ (`@gm/domain` + `@gm/time`)

- `packages/time/src/elapsed.ts`: `addElapsed` เวลาจริง (lease / back-off) — ไม่ใช่วันทำการ
- `packages/domain/src/scheduled-work.ts`: `TICK_SCHEDULE` (`*/15 * * * *`, Asia/Bangkok), `TICK_LEASE_MS` 10 นาที (< รอบ 15 นาที ⇒ worker ที่ตายไม่บล็อก tick ถัดไป), `TICK_WORK_BUDGET_MS` 5 นาที, `TICK_STEPS` (outbox recovery → scheduled_work), `SCHEDULED_WORK_KINDS` (stale, auto_close, presence_reset, digest, renewal, aggregate_reconcile, backup, cleanup — ครบตาราง §6.9 รวม outbox recovery), `BOUNDED_RETRY` 5 ครั้ง เว้น 5/15/60/240 นาที (Q-A02-1), `claimTick`, `claimJob`, `settleJob`, `JOB_LEASE_MS` 5 นาที
- `packages/domain/src/delivery.ts`: สถานะตาม Part 6 (`pending`/`processing`/`provider_accepted`/`failed`/`delivery_unknown`/`suppressed`), `chooseDeliveryChannel` (A1.2), `claimDelivery`, `settleDelivery`, `DELIVERY_LEASE_MS` 5 นาที

| เหตุ | สถานะต่อไป |
|---|---|
| `pending` ถึงเวลา → claim (transaction) | `processing` + `lease_until` + `delivery_channel` + `attempts+1` |
| ผู้ให้บริการรับ | `provider_accepted` + `provider_id` |
| ล้มเหลวแบบลองใหม่ได้ ยังไม่ครบ 5 ครั้ง | `pending` + `next_attempt_at` ตาม back-off + `last_error_code` |
| ล้มเหลวครบ 5 ครั้ง / ปฏิเสธถาวร (เช่น `CHANNEL_DISABLED`) / ไม่มีช่องทาง (`NO_CHANNEL`) | `failed` (คง `last_error_code`) |
| ผลไม่แน่นอน / adapter โยน error (`ADAPTER_ERROR`) / worker ตายระหว่างส่งจน lease หมด (`LEASE_EXPIRED`) | `delivery_unknown` — **ไม่ส่งซ้ำแบบเดา** (§6.10), GM ตรวจ (Q-A02-2) |
| งานถูกลบ (`REQUEST_NOT_FOUND`) / ยกเลิกแล้วสำหรับประกาศสร้างงาน (`REQUEST_CANCELLED`) | `suppressed` |

### Dev manual tick — รันจริงบน emulator

`firebase emulators:exec --project demo-gm-local --only firestore` + seed รายการ outbox ผ่าน REST ของ emulator + `tsx apps/worker/src/main.ts` (PORT 8790) + `npm run tick:local -w @gm/worker`:
- tick แรก `200 {"ran":true,"outbox":{"sent":1,…},"more":false}` → รายการเป็น `provider_accepted`, `delivery_channel: email`
- tick ที่สอง `200 {"ran":true,"outbox":{"sent":0,…}}` (ไม่ส่งซ้ำ)
- log ของ worker มีเฉพาะ event/outbox_id/channel/state ไม่มีอีเมลผู้รับ

## คำถามค้าง (ไม่เดา — ใช้ค่าเสนอไว้ก่อนและรอยืนยัน)

1. **Q-A02-1 ตัวเลข retry** — Part 6 บอกแค่ “bounded retry/backoff” ตอนนี้ใช้ 5 ครั้ง เว้น 5/15/60/240 นาที (รวม ~5 ชม. 20 นาที; tick 15 นาทีจึงหยิบได้ช้าสุด +15 นาที) ใช้ชุดเดียวกันทั้ง outbox และ `scheduled_work` — ยืนยันหรือกำหนดค่าใหม่
2. **Q-A02-2 worker ตายระหว่างส่ง** — ตีความ §6.10 (“ไม่อ้าง exactly-once … ไม่ส่งสองทางแบบเดา”) ว่า `processing` ที่ lease หมด → `delivery_unknown` ไม่ส่งซ้ำอัตโนมัติ; การ “ลองใหม่” ของ GM (UI-15) จะเป็นคำสั่งแยกที่ตรวจว่ายังไม่เคยสำเร็จ — ยืนยัน และคำสั่งนี้อยู่ task ไหน (A06/A17/A24)
3. **Q-A02-3 ไม่มีช่องทาง / adapter ปิด** — ตอนนี้เป็น `failed` + `NO_CHANNEL` / `CHANNEL_DISABLED` (ไม่ใช่ `suppressed` ซึ่งใช้กับงานยกเลิก/ลบ) และเมื่อเปิด adapter ภายหลัง รายการเดิมไม่ถูกส่งย้อนหลังอัตโนมัติ — ยืนยัน
4. **Q-A02-4 ผู้ขอที่เป็นผู้รับฝั่ง GM ด้วย** — (GM อีกคนเปิดแทน GM ที่เป็น default owner) ได้รายการเดียวแบบ `gm` ตามกติกา 1 รายการต่อผู้รับ — ยืนยัน หรือให้ได้ข้อความผู้ขอแทน
5. **Q-A02-5 การแสดงผลให้ GM** — A02 เก็บข้อมูลครบใน outbox แต่ยังไม่มีหน้าจอ/API ให้ GM ดู ([FU-23](../FOLLOW-UPS.md) เสนอ A06 ป้าย + A17 ตารางรายผู้รับ); หน้า Admin “tick สำเร็จล่าสุด / outbox fail” (§6.13) จะอยู่ task ไหน
6. **Q-A02-6 ค่า Cloud Run/Scheduler** — เสนอ worker request timeout ≥ 600 วินาที, Scheduler `attempt_deadline` 600 วินาที และ `retry_count: 0` (tick ถัดไปเก็บงานต่ออยู่แล้ว) ใน `infra/scheduler.json` — ผู้ดูแลยืนยันตอน P7-INFRA-01

## Risk ที่ยังค้าง

- Cloud Tasks ยังไม่ต่อ (FU-20 ส่วนที่เหลือ): แจ้งเตือนช้าได้ถึง 15 นาที (รอ tick) จนกว่าจะได้ queue/region/SA จาก P7-INFRA-01
- ข้อความจริง (template, งานลับ = เลข + ข้อความกลาง + ลิงก์) และการตรวจสิทธิ์ผู้รับตอนส่งของเหตุการณ์อื่น ๆ อยู่ A07/A08; A02 ส่งผ่าน adapter local เท่านั้น
- ตอนรัน worker/API บนเครื่องด้วย `initializeApp()` (โหมด dev) firebase-admin ลองถาม metadata server ของ cloud หนึ่งครั้งแล้วเตือน `MetadataLookupWarning` (ไม่ได้ต่อ project จริง ใช้ emulator ต่อได้ปกติ; ใส่ `projectId` แล้วไม่หาย) — test ใช้ credential ทิ้งได้จึงไม่เจอ
- `gm-worker` ยังไม่ได้ทดสอบหลัง Cloud Run IAM จริง (A26)
