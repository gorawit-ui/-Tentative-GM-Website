### HTTP (`apps/api/src/http/app.ts`, ปิดส่วน HTTP ของ FU-16)

| Route | งาน |
|---|---|
| `POST /api/commands` | `create_maintenance` / `create_on_behalf` / `create_gm_task` / `watch_request` |
| `GET /api/requests/:id`, `/history`, `/comments` | endpoint ของ S12 |
| `GET /api/me/requests`, `GET /api/me/awaiting-confirmation` | คำขอของฉัน / จำนวนรอยืนยัน (D-S10-2) |

| `GET /healthz`, `OPTIONS *` | health / CORS preflight |

- ทุกคำขอ: `Authorization: Bearer <ID token>` → `verifyIdToken` (firebase-admin) → `isCorporateGoogleToken` (Google, verified, @tdfb.co หลัง `lower()` — D-S10-5) → อ่าน `access/{uid}` ใหม่ (role, `enabled`) — custom claim ไม่มีผล
- CORS (`http/cors.ts`): prod `https://gm.tdfb.co`, dev `https://gm-dev.tdfb.co`, local `http://localhost|127.0.0.1:5173|4173` (Vite dev/preview); `GM_ALLOWED_ORIGINS` แทนค่าเริ่มได้ (เฉพาะ origin แบบตรงตัว https, ไม่มี `*`, http ได้แค่ loopback ใน local); ไม่มี `allow-credentials` (ใช้ bearer token); origin ไม่อยู่ในรายการ → preflight 403 และคำขอจริง 403 `ORIGIN_NOT_ALLOWED` ก่อนทำอะไร; ไม่มี Origin (เรียกผ่าน Hosting rewrite แบบ same-origin หรือจาก server) → ผ่าน
- body JSON ≤ 64 KiB (413 `BODY_TOO_LARGE`), JSON เสีย 400 `BODY_INVALID`, contract error 400 + `path`, domain refusal → 403/404/409/422/503 ตาม code, อื่นๆ 500 `INTERNAL`; ทุก response `cache-control: no-store`, `x-content-type-options: nosniff`
- log ต่อคำขอ 1 บรรทัด: `http.request` + ชื่อ route + status + code เท่านั้น (ไม่มี path จริง header body หรือ token)

### คำสั่งสร้างงาน — transaction เดียว (`apps/api/src/commands/execute-command.ts`)

อ่านทั้งหมดก่อนเขียน: command เดิม → catalog → ตัวนับ → `settings/routing` + GM members (`people` active + `gm_profiles` presence) + `calendars/company` → ชื่อ (`people`) → `board_counters/public` (งานลับ) แล้วเขียน:

1. `system_counters/request_sequence`
2. `requests/{id}` (มี `assignee_id` จาก routing + คู่ชื่อ D-S10-1/D-S11-1)
3. `gm_request_details/{id}`, `gm_request_summaries/{id}` (stale ใช้ปฏิทินบริษัท), `request_summaries/{id}` (เฉพาะงานไม่ลับ) หรือเพิ่ม `board_counters/public.internal_board_count` (งานลับ, D-S09-4)
4. `requests/{id}/history/created` (`request_created`, ผู้ทำ, routing reason, assignee)
5. `user_state/{ผู้ขอ}/requests/{id}` (`requester`) และของ related แต่ละคน (`related`)
6. `outbox/{hash}` หนึ่งรายการต่อผู้รับ: `request_created`, `channel: auto`, `state: pending`, `attempts: 0`, `confidential` — ผู้รับจาก routing (assignee หรือ “GM ทุกคน” ที่ไม่ลา) **ไม่รวมผู้ทำ action** (D-S08-2); ID เป็น hash ไม่มีอีเมล
7. `commands/{command_id}` (fingerprint + ผลลัพธ์ + `expire_at` TTL)

หลัง commit HTTP ส่ง outbox ID ให้ `taskQueue` — ล้มเหลวก็ตอบ 200 และ log `outbox.enqueue_failed` (count เท่านั้น) งานและ outbox `pending` ยังอยู่ให้ recovery (A02, [FU-20](../FOLLOW-UPS.md)); **ไม่มีการส่ง Slack/email** ใน A01

ไม่มี `settings/routing` → 503 `ROUTING_NOT_CONFIGURED`, ไม่มี `calendars/company` → 503 `CALENDAR_NOT_CONFIGURED` (ไม่เดาค่า; ค่าจริงจาก P7-ADMIN-04); `main.ts` ยังปฏิเสธแจ้งซ่อมด้วย `CATALOG_NOT_READY` จนกว่า A11/A12 ([FU-19](../FOLLOW-UPS.md))

## คำถามค้าง (ไม่เดา)

1. **Q-A01-1 CORS ของ dev** — Part 6 ไม่ระบุ CORS (มีแค่ Hosting rewrite `/api/**` แบบ same-origin) และ domain ยังเป็นค่าเสนอ (P7-INFRA-01) ตอนนี้ API dev รับเฉพาะ `https://gm-dev.tdfb.co`, localhost รับเฉพาะ environment `local` — ต้องให้ API dev รับเว็บที่รันบนเครื่อง (`localhost:5173`) ด้วยหรือไม่
2. **Q-A01-2 รายชื่อ GM และ default owner เก็บที่ไหน** — ตอนนี้อ่านจาก `settings/routing` (`default_owner_by_type`, `gm_person_ids`) + `people/{id}.active` + `gm_profiles` และถ้าไม่มี settings/ปฏิทินจะปฏิเสธการสร้างงาน (503) แทนการสร้างแบบไม่มีคนรับแจ้ง — ยืนยันโครงนี้สำหรับ A10/A11
3. **Q-A01-3 ช่องทางใน outbox** — Part 6 ให้ key = event + recipient + channel ตอนนี้บันทึก 1 รายการต่อผู้รับด้วย `channel: auto` ให้ adapter (A07/A08) เลือก Slack DM ถ้าจับคู่ได้ ไม่งั้น email บริษัท — หรือควรแยก entry ต่อช่องทางตั้งแต่ตอนสร้าง
4. **Q-A01-4 แจ้งผู้ขอตอนสร้างงานหรือไม่** — ตอนนี้แจ้งเฉพาะฝั่ง GM (assignee/GM ทุกคน) ผู้ขอเห็น “รับคำขอแล้ว” บนหน้าจอ (Part 3 UI-03) ไม่มี outbox ถึงผู้ขอ
