## ส่วนที่ 2 — S06 waiting (`@gm/domain` `waiting.ts`, pure)

ทุกคำสั่งรับ state + `now` + actor คืน state ใหม่ + history event (บางคำสั่งคืน notice/reminder ให้ outbox ภายหลัง) **ไม่ส่งอะไรจริง** ไม่เขียน Firestore

| Command | ใคร | จาก → ไป | ผล |
|---|---|---|---|
| `planWaiting` | (preview) | — | ตรวจ `waiting_on`, คำนวณผู้รับแจ้ง, คนที่จะเพิ่มเป็น related, ต้องยืนยันสิทธิ์งานลับหรือไม่ (F05 §9.2) |
| `enterWaiting` | GM | `in_progress` → `waiting` | interval ใหม่ (`currentWaitingIntervalId`, `waitingSince`, `waitingRecipientIds`, `waitingPartyResponded: false`), เพิ่มผู้รับเป็น related, `lastUpdatedAt` = now, คืน `notice` การแจ้งครั้งแรก |
| `changeWaitingParty` | GM | `waiting` → `waiting` | จบ interval เดิม (`exitedAt` = now, คง `respondedAt`) ใน event แล้วเปิด interval ใหม่; ล้างผลตอบของฝ่ายเดิม |
| `followUp` | GM | `waiting` | event `followed_up` + `lastUpdatedAt` = now; `waitingSince` คงเดิม; `remind: true` → ตรวจโควตา |
| `respondWaitingParty` | ผู้รับแจ้งของช่วงปัจจุบัน | `waiting` | `waitingPartyResponded: true` + `respondedAt`; ไม่เปลี่ยน status/`waiting_on`/`waitingSince`/`lastUpdatedAt` |
| `resumeWork` | GM | `waiting` → `in_progress` | จบ interval (`exitedAt` = now) ล้าง field ช่วงปัจจุบัน `lastUpdatedAt` = now |
| `cancelRequest` (S05) | GM | `waiting` → `cancelled` | ตอนนี้จบ interval ที่เปิดอยู่ด้วย (`endedWaitingInterval` ใน event) |

- **`waiting_on` (F3, C3)** ไม่มีค่าเริ่มต้น: ไม่ส่ง/ไม่มี kind → `WAITING_ON_REQUIRED`; `person` ต้องมี `personId`; `team` ต้องมี `teamLabel` ผู้ติดต่อ 0–3 คนไม่ซ้ำ; `contractor`/`government`/`other` ต้องมี `name`; field ของ kind อื่น → `WAITING_ON_INVALID`; เก็บเฉพาะ field ของ kind นั้น ตัดช่องว่าง
- **ผู้รับแจ้ง (F05 §9.1)**: person แจ้งเป็นค่าเริ่มต้น GM ปิดได้ (`notify: false`); team แจ้งผู้ติดต่อที่เลือก (ไม่มีผู้ติดต่อ = ไม่แจ้ง); contractor/government/other ไม่แจ้ง; ขอแจ้งเมื่อไม่มีผู้รับ → `NOTIFY_NOT_AVAILABLE`
- **related/งานลับ (C3, C4, F3)**: ผู้รับแจ้งที่ยังไม่มีสิทธิ์ (ไม่ใช่ผู้ขอ/related) ถูกเพิ่มใน `relatedPersonIds`; งานลับที่มีคนใหม่ต้อง `confirmConfidentialGrant: true` ไม่งั้น `CONFIDENTIAL_GRANT_REQUIRED`; ปิดการแจ้งแล้วยังเข้ารอได้โดยไม่เพิ่มสิทธิ์
- **เตือนซ้ำ (C3, Part 6 §6.14)**: 1 ครั้งต่อวันทำการต่องาน ใช้ `businessDateBucket` ใหม่ใน `@gm/time`: วันเปิด → `send_now` + `remindedAt`; ซ้ำวันเดิม → `quota_used` (ยังบันทึกติดตามแล้ว); วันปิด → `next_business_day` ใช้โควตาของวันทำการถัดไป (ไม่เพิ่มโควตา); เปลี่ยนฝ่ายในวันเดียวกันก็ยังนับโควตาเดิม (ต่องาน); ไม่มีผู้รับ → `REMINDER_NO_RECIPIENTS`
- **ตอบกลับ (A2)**: ตรวจตามลำดับ Trello → `NOT_WAITING` → interval เก่า `STALE_WAITING_INTERVAL` → contractor/government/other `NO_RESPONSE_FOR_PARTY` → ไม่อยู่ในผู้รับของช่วงปัจจุบัน `NOT_CURRENT_RECIPIENT` (watcher, Viewer, related, ผู้ขอ, GM, สมาชิกทีมที่ไม่ได้เลือก) → ถูกถอนสิทธิ์ `ACCESS_REVOKED` → ตอบแล้ว `ALREADY_RESPONDED` (คำตอบแรกของทีมนับแทนทั้งทีม)
- **เวลารอ (S02)**: `currentWaitingInterval(state)` และ `EndedWaitingInterval` ใช้กับ `effectiveWaitingEnd`/`waitingElapsed` ของ S02 ได้ตรง — ตัวอย่าง A2.3 เข้า 10:00 ตอบ 12:00 กลับมาทำต่อ 14:00 → เวลาของฝ่ายนั้น 2 ชั่วโมง; contractor ไม่มีคำตอบ → จบที่ 14:00 (4 ชั่วโมง)
- `@gm/time` เพิ่ม `businessDateBucket(instant, calendar)` → `{ businessDate: 'YYYY-MM-DD', isOpenDay }` ตามวันของ Asia/Bangkok
- โครงสร้าง: ย้าย `LifecycleRejected` และ guard ที่ใช้ร่วม (`requireGmActor`, `requireStatus`, `requireReason`, `requireWritable`) ไป `command-guards.ts` (พฤติกรรมเดิม test เดิมผ่าน); `lifecycle.ts` ยัง re-export `LifecycleRejected`
