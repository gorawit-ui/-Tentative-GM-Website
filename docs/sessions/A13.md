## ส่วนที่ 2 — A13 กันแจ้งซ้ำ (U1)

### กติกาการจับคู่ (domain `packages/domain/src/duplicates.ts`, pure)

- เทียบ **สถานที่ + บริเวณ + อาการ** จากค่าที่เลือก ไม่เทียบ `summary_title` (GM แก้ได้)
- เฉพาะงาน `maintenance` ที่ `queued` / `in_progress` / `waiting` และไม่มี `closed_at`; **ไม่รวม** งานลับ, งาน `completed` ที่รอยืนยัน (ติดตามไม่ได้ตาม D-S08-7), ปิด/ยกเลิก
- อาการ “อื่นๆ” ไม่จับคู่เลย (หน้าเว็บไม่เรียก API ด้วย)
- บริเวณระบุทั้งสองฝั่งและต่างกัน → ไม่เสนอ; “ไม่ระบุ” ฝั่งใดฝั่งหนึ่ง → เทียบสถานที่ + อาการ (ผู้ใช้ยืนยันเอง)
- เรียงงานที่แจ้งก่อนขึ้นก่อน; `viewerRelation` บอกว่าผู้อ่านเป็นผู้ขอ / ติดตามอยู่แล้ว / ไม่เกี่ยว; `watchNote` หมายเหตุไม่บังคับ ตัดช่องว่าง ≤ 1,000 ตัวอักษร (ค่าจาก prototype — Q-A13-1)

### API

- `GET /api/repair/duplicates?location_id=…&area_id=…&symptom_key=…` — ทุกบัญชีที่ใช้งานอยู่ (แจ้งซ่อมได้ทุก role D-S04-6), ก่อน login 401, ปิดบัญชี 403, ค่าผิด 400 `QUERY_INVALID`
  - query `request_summaries` (สถานที่ + อาการ + สถานะเปิด, ≤ 20) แล้วอ่าน `requests/{id}` (ธงลับ — ไม่มี record หรือไม่ได้บอกว่าไม่ลับ = ไม่เสนอ, ผู้ขอ) และ `gm_request_details/{id}` (watcher) **เพื่อบอกความสัมพันธ์ของผู้อ่านเท่านั้น**
  - ตอบเฉพาะ field สรุปที่เปิดเผยได้: `request_id`, `request_number`, `summary_title`, `status`, `is_assigned`, `assignee_label`, `location_label`, `area_label`, `watcher_count`, `created_at`, `viewer` (`requester` / `watcher` / `none`) — ไม่มีรายละเอียด ชื่อ/อีเมลผู้แจ้ง รายชื่อ watcher คอมเมนต์ รูป หรือ history
  - `findDuplicateMatches(db, personId, selection)` export ไว้ให้ **A14 เรียกซ้ำตอนกดส่ง** ([FU-49](../FOLLOW-UPS.md))
- `watch_request` รับ `note` (ไม่บังคับ): ครั้งแรกที่ติดตาม (`added`) เพิ่มใน `watcher_ids` (`gm_request_details`), `watcher_count` + 1 ทั้งสรุปสาธารณะและ GM, `user_state` แบบ watcher, และถ้ามีหมายเหตุเขียน contribution ที่ `requests/{id}/gm_history/contribution-{hash}` (`kind: watcher_contribution`, `note`, `photo_count: 0`) — GM อ่านเท่านั้น ไม่อยู่ใน `history` ที่ผู้ขอเห็น; ไม่สร้างงาน ไม่ใช้เลขงาน ไม่ขยับ `last_updated_at`/stale; กดซ้ำ → `already_watching` ไม่เพิ่มจำนวน หมายเหตุแรกคงอยู่; ผู้ขอกด → `is_requester` ไม่เขียนอะไร; หมายเหตุเกิน 1,000 → 422 `NOTE_TOO_LONG`; งานเสร็จรอยืนยัน → 422 `WATCH_NOT_OPEN` (เดิม)

### หน้าจอ (UI-03 ระหว่างขั้น 3 กับ 4)

- กด “ถัดไป” ที่ขั้น 3 (อาการไม่ใช่ “อื่นๆ”) → “กำลังตรวจว่ามีคนแจ้งเรื่องนี้แล้วหรือไม่…” → ไม่มีงานตรง: ไปขั้น 4 ทันที (ไม่มีหน้าคั่น); มีงานตรง: หัวข้อ **“มีคนแจ้งเรื่องนี้แล้ว”** + “ใช่เรื่องเดียวกันไหม? ติดตามงานเดิมได้โดยไม่ต้องแจ้งซ้ำ” + การ์ดต่องาน: เลขงาน, ป้ายสถานะ (รอคิว/กำลังทำ/รอผู้อื่น บนสีสถานะของ Part 4), ชื่อสรุป, “ผู้รับผิดชอบ: …” หรือ “ยังไม่มอบหมาย”, “มีผู้แจ้งเพิ่ม X คน”
  - ผู้อ่านไม่เกี่ยว: ปุ่ม **“ใช่ เรื่องเดียวกัน — ติดตามเรื่องนี้”**
  - ผู้ขอของงานนั้น: **“คุณแจ้งเรื่องนี้ไว้แล้ว”** + ลิงก์ “ดูงานของคุณ” (`/requests/{id}`) ไม่มีปุ่มติดตาม
  - ติดตามอยู่แล้ว: **“คุณติดตามเรื่องนี้อยู่แล้ว”** + ลิงก์ “ดูข้อมูลสรุป” ไม่มีปุ่มติดตาม
  - แถบล่าง: “ย้อนกลับ” (กลับไปเลือกอาการ) / **“ไม่ใช่ แจ้งเรื่องใหม่”** → ขั้น 4 โดยค่าที่เลือกครบ (สถานที่ บริเวณ อาการ ชื่ออัตโนมัติ); งานที่ตอบ “ไม่ใช่” แล้วไม่ถามซ้ำในฟอร์มเดียวกัน
- dialog **“ติดตามเรื่องนี้”**: เลขงาน · ชื่อ, “ดูข้อมูลสรุปและรับแจ้งสถานะ โดยไม่ได้สิทธิ์รายละเอียดของผู้แจ้งคนแรก”, ช่อง “หมายเหตุเพิ่มเติม (ส่งได้ครั้งเดียว ไม่บังคับ)” (≤ 1,000), “แนบรูปเพิ่มได้ในรุ่นถัดไป”, ปุ่ม “ย้อนกลับ” / “ยืนยันติดตาม” (command ID เดียวต่อ dialog กดซ้ำหลังเน็ตหลุดเป็นคำสั่งเดิม)
- สำเร็จ: **“ติดตามงานนี้แล้ว”** + เลขงาน ชื่อ “คุณจะได้รับแจ้งเมื่อสถานะเปลี่ยนและเมื่อเสร็จ โดยไม่ต้องยืนยันปิดงาน” “ไม่ได้สร้างงานใหม่ …” + “ดูข้อมูลสรุป” / “กลับหน้าแรก”
- งานปิด/เสร็จไประหว่างนั้น (`WATCH_NOT_OPEN`): “งานนี้ปิดหรือเสร็จไปแล้ว ติดตามไม่ได้” แล้วตรวจใหม่ (ไม่มีงานเปิด → ขั้น 4)
- ตรวจไม่สำเร็จ: **“ตรวจงานซ้ำไม่ได้”** “ยังไม่รู้ว่ามีคนแจ้งเรื่องนี้แล้วหรือไม่ …” + “ลองอีกครั้ง” / “แจ้งเรื่องใหม่ต่อ” — ไม่บอกว่าไม่มีงานซ้ำ
- CSS ใน `styles/repair.css` (import เข้า layer `components`), สีจาก token; การ์ดและปุ่มเต็มความกว้างบนมือถือ ปุ่ม ≥ 44 px; ไอคอน `bell` จาก prototype
