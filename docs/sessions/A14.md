## ส่วนที่ 2 — A14

### ขั้น 4 (UI-03, U2)

- หัวข้อ “รายละเอียด”; ชื่อบนบอร์ดแสดงแบบอ่านอย่างเดียว (`repair-title-preview` ไม่มีช่องแก้, U2) และเปลี่ยนตามเมื่อย้อนกลับไปแก้
- ช่องข้อความ: อาการทั่วไป “รายละเอียดเพิ่มเติม (ไม่บังคับ)”; **“อื่นๆ” → “อธิบายอาการ (ต้องกรอก)”** — ว่างแล้วกดส่ง: “อธิบายอาการก่อนส่ง” + โฟกัสช่อง ไม่ส่งอะไร; API/domain บังคับเหมือนกัน (`DESCRIPTION_REQUIRED` ทั้งผู้ขอเองและ GM เปิดแทน); บอกใต้ช่องว่าข้อความนี้ทีม GM และผู้ขอเห็นเท่านั้น ไม่ขึ้นบนบอร์ด (ข้อความอยู่ใน `requests/{id}.description` ที่จำกัดสิทธิ์ ไม่ใช่ชื่อหรือสรุปสาธารณะ — test emulator ยืนยัน)
- **ไม่มีส่วนแนบรูป** — การแนบรูปเป็นงานของ **A15** (ย่อรูป/ตัวเลือก/ความคืบหน้า, ≤ 3 รูปตาม D-S12-3) จึงไม่แสดงส่วนที่ยังใช้ไม่ได้ (test ยืนยันว่าไม่มี `input[type=file]`)
- แถบล่าง: “ย้อนกลับ” / **“ส่งเรื่อง”** อยู่ในจอเสมอ (แถบ 64 px บนมือถือ F6)

### การส่ง (U1 “กันส่งพร้อมกัน”, UI-03 states)

- **`command_id` เดียวต่อฟอร์มหนึ่งชุด** สร้างครั้งเดียว ใช้ซ้ำทุกครั้งที่ลองส่ง (เก็บในร่างด้วย จึงรอดการ reload); ระหว่างส่งปุ่มเป็น “กำลังส่ง…” กดไม่ได้; API คืนผลเดิมเมื่อ `command_id` ซ้ำ (A01) → **งานเดียว เลขเดียว**
- เน็ตหลุด/ไม่มีคำตอบ: “ยังไม่แน่ใจว่าส่งถึงหรือไม่ … กด “ส่งอีกครั้ง” ได้เลย ระบบจะไม่สร้างงานซ้ำ”; ถ้าครั้งก่อนส่งถึงแล้วแต่ข้อความเปลี่ยนไป API ตอบ `COMMAND_ID_CONFLICT` → “เรื่องนี้ส่งไปแล้วจากการกดครั้งก่อน … ดูได้ในคำขอของฉัน”
- **ตรวจงานซ้ำอีกครั้งตอนกดส่ง (FU-49)**: ใน transaction สร้างงาน API อ่านเอกสารกั้น `duplicate_guards/{hash สถานที่+อาการ}` แล้ว query งานเปิดที่ตรงกัน (`request_summaries` ตาม index ของ A13, ≤ 20 งาน, กติกา U1 ชุดเดียวกับ A13 — “อื่นๆ” ไม่ตรวจ) แล้วเขียนเอกสารกั้นเมื่อสร้าง → การส่งเรื่องเดียวกันพร้อมกันเรียงกัน คนหลังเห็นงานของคนแรก; มีงานที่ยังไม่ได้ตอบ “ไม่ใช่” → **409 `DUPLICATE_FOUND` (`request_ids`)** ไม่เขียนอะไร ไม่ใช้เลข; หน้าเว็บกลับหน้าคั่น (“ย้อนกลับไปแก้รายละเอียด” ด้านบน ข้อความที่กรอกยังอยู่) — “ใช่ ติดตามเรื่องนี้” หรือ **“แจ้งเรื่องใหม่” ส่งต่อทันทีพร้อม `known_duplicate_ids` ไม่ถามซ้ำ** (API สร้างได้หนึ่งงาน); 15 คนส่งเรื่องเดียวกันพร้อมกัน → 1 งาน อีก 14 คนเห็นงานนั้น (test emulator)
- ส่งสำเร็จ: **“ส่งเรื่องเรียบร้อยแล้ว”** + เลขงาน + ชื่อบนบอร์ด + “ทีม GM ได้รับแจ้งแล้ว ติดตามความคืบหน้าได้ในคำขอของฉัน” + ผู้รับผิดชอบจริง (“ผู้รับผิดชอบ: … · สถานะ รอคิว” หรือ “ยังไม่มอบหมาย — รอทีม GM รับเรื่อง”, UI-03) + ปุ่ม **“ดูงานของฉัน”** (`/requests/{id}`) / “กลับหน้าแรก”; คำตอบของ create เพิ่ม `status`, `is_assigned`, `assignee_label`
- **503** (`PLACES_NOT_SET_UP` / `ROUTING_NOT_CONFIGURED` / `CALENDAR_NOT_CONFIGURED`): “ระบบแจ้งซ่อมยังตั้งค่าไม่ครบ ยังส่งเรื่องจากหน้านี้ไม่ได้” + เหตุ + กล่อง “ติดต่อทีม GM” ข้อมูลที่กรอกยังอยู่ (FU-21)
- error อื่น: สถานที่/บริเวณ/อาการถูกปิดระหว่างกรอก (`LOCATION_UNAVAILABLE` / `AREA_UNAVAILABLE` / `SYMPTOM_UNKNOWN`) → บอกเหตุ + ปุ่ม “เลือกสถานที่ใหม่”; 401/403 → “บัญชีนี้ส่งเรื่องไม่ได้ตอนนี้ เข้าสู่ระบบใหม่ หรือติดต่อทีม GM”; อื่น ๆ → “ส่งไม่สำเร็จ ข้อมูลที่กรอกยังอยู่ ลองส่งอีกครั้ง ถ้ายังไม่ได้ติดต่อทีม GM” + ปุ่ม “ส่งอีกครั้ง”

### จำค่าที่กรอกค้าง (FU-47, D-A12-5)

`apps/web/src/repair/repair-draft.ts`: `sessionStorage` ของ tab เท่านั้น (key `gm.repair.draft`) เก็บ ขั้น สถานที่ บริเวณ อาการ ข้อความ `command_id` และรายการที่ตอบ “ไม่ใช่” (Q-A14-1) — **ไม่มีรูป** (ฟังก์ชันเขียนเฉพาะ field ที่ระบุ); ผูกกับคนที่เขียน (คนอื่นที่ใช้ tab เดียวกันไม่เห็น ร่างถูกลบ); ลบเมื่อส่งสำเร็จ; **logout ล้าง `sessionStorage` ทั้งหมด** (A09 `device.ts`) — test e2e ยืนยัน; tab ใหม่เริ่มว่าง; สแกน QR ใหม่ชนะร่าง (Q-A14-4); storage ใช้ไม่ได้ (private mode/เต็ม) ฟอร์มยังทำงาน

## Risk ที่ยังค้าง

- ยังแนบรูปไม่ได้จนกว่า A15; ยังไม่มีหน้า “คำขอของฉัน”/รายละเอียดงานจริง (ลิงก์ “ดูงานของฉัน” ไปหน้ารอ) จนกว่า A16/A17
- จุด “มีอัปเดตใหม่” ฝั่ง GM มีข้อมูลแล้วแต่ยังไม่มีบอร์ด GM ให้แสดง (FU-50 → A18)
- query ตรวจซ้ำใน transaction ใช้ index รวมของ A13 — emulator ไม่ตรวจ index; ต้องยืนยันบน project จริงตอน deploy dev (ผู้ดูแล)
- `duplicate_guards` เป็น collection ใหม่ (API เท่านั้น, Rules ปฏิเสธ client ทุก role ตาม default deny) — ไม่มีการลบเอกสารเก่า (หนึ่งเอกสารต่อสถานที่+อาการ ขนาดเล็ก จำนวนจำกัด)
- e2e ในเครื่องนี้: Playwright ที่ pin (1.56.1) หา headless shell รุ่นที่ติดตั้งไว้ไม่เจอ จึงลิงก์ path ไปยัง browser ที่มีในเครื่อง (`/opt/pw-browsers`, นอก repo) — ไม่กระทบ repo
