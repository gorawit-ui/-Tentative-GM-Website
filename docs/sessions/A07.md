### Slack adapter (`apps/worker/src/slack.ts`)

- `chat.postMessage` ครั้งเดียวต่อ attempt: `channel` = Slack user ID ของผู้รับ (DM), `Authorization: Bearer <bot token>`, JSON; ไม่ retry เอง — การลองใหม่เป็นของ dispatcher (A02)
- ผลที่ได้ → สถานะของ outbox:

| คำตอบของ Slack | ผล adapter | สถานะรายการ |
|---|---|---|
| `ok: true` | accepted `slack:{channel}:{ts}` | `provider_accepted` |
| ไม่มี Slack ID / `user_not_found` / `channel_not_found` | unmapped (ยังไม่ได้ส่ง) | ส่ง **email บริษัทใน attempt เดียวกัน** (A1.2) → `delivery_channel: email`; ถ้าไม่มีทาง email → `failed SLACK_NOT_MAPPED` |
| HTTP 429 / `ratelimited` + `Retry-After` | retryable `SLACK_RATE_LIMITED` + `retryAfterMs` | `pending`, `next_attempt_at` = max(back-off A02 5/15/60/240 นาที, Retry-After) — นับรวมใน 5 ครั้ง; Retry-After เกิน 24 ชม. ถือเป็น 24 ชม. |
| ต่อไม่ติดก่อนส่ง (ECONNREFUSED/DNS) / HTTP 503 / `service_unavailable` | retryable | `pending` ตาม back-off |
| ส่งแล้วไม่ตอบภายใน timeout (ค่าเริ่มต้น 10 วินาที) / HTTP 5xx อื่น / `internal_error`, `fatal_error`, `request_timeout` / คำตอบอ่านไม่ได้ | unknown (อาจโพสต์แล้ว) | `delivery_unknown` — **ไม่ส่งซ้ำเอง** ให้ GM ตรวจ (ปุ่มส่งอีกครั้ง FU-23) |
| error อื่น เช่น `user_disabled`, `account_inactive`, `invalid_auth`, `missing_scope` / HTTP 4xx | permanent `SLACK_<ERROR>` | `failed` พร้อมรหัส; ผู้ขอ → ป้าย “ผู้ขอยังไม่ได้รับแจ้ง” (A06) |

- log: มีแค่ event + outbox ID + รหัส (logger allowlist ของ A02) — ไม่มี token, Slack ID, email, ชื่อ, เลขงาน, ข้อความ (test ตรวจ log ทั้งไฟล์)

### dispatcher / runtime

- claim transaction อ่านเพิ่ม (ก่อนเขียน): `summary_title` จาก `requests/{id}` (เฉพาะงานไม่ลับ) และ `request_summaries/{id}.waiting_on_summary` เฉพาะ `request_waiting` ของงานไม่ลับ
- `channelRouter({ slack, email })` ส่งตามช่องทางที่ dispatcher เลือก; `notificationAdapter(mode, log, { webBaseUrl })` — โหมด runtime **ยังมีแค่ `local` / `disabled`** (`GM_NOTIFICATION_ADAPTER=slack` ยังถูกปฏิเสธตอนเริ่ม) จนกว่า P7-ADMIN-03 อนุมัติ Slack app + sandbox recipients (FU-33); `disabled` → `failed CHANNEL_DISABLED` งานไม่เปลี่ยน
- ประกาศ “งานใหม่” ถึง GM ทุกคนเพราะไม่มีผู้รับผิดชอบ (ค่าเริ่มต้นลา / ปิดใช้ / ไม่ได้ตั้ง) มี `notice_variant: unassigned` → “ยังไม่มอบหมาย รอทีม GM รับเรื่อง”
