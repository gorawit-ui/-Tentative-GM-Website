- `corporateSignIn()`: `request.auth != null`, `firebase.sign_in_provider == 'google.com'`, `email_verified == true`, `email.matches('^[a-z0-9._%+-]+@tdfb[.]co$')` (ตรงตัว: จุดถูก escape, anchored ทั้งสองด้าน, ตัวพิมพ์เล็ก)
- `accessOf()` = `get(/databases/$(database)/documents/access/$(request.auth.uid)).data` เป็น document read **เดียว** ในไฟล์ เรียกไม่เกินหนึ่งครั้งต่อ `allow`; `isActive(a)` = `enabled == true` (ต้องเป็น boolean); `isGm(a)` = active + role `gm_staff`/`gm_admin` จาก access document (custom claim ไม่มีผล)

- active: `request_summaries`, `gm_profile_summaries`, `locations`, `areas`, `qr_codes`, `content_pages`, `announcements`; get `board_counters/public`
- GM: `gm_request_summaries`, `gm_request_details`, `people_picker`, `renewal_items` (+ `cycles`)
- ของตัวเอง: `user_state/{person_id}/requests/{id}` (active + `person_id` ตรง), `access/{uid}` get (D-S09-6 บัญชีปิดใช้งานก็อ่านได้)

## คำถามค้าง (ไม่เดา — ไม่แก้สิทธิ์เอง)

1. **Q-S10-1 ชื่อคนบนหน้ารายละเอียดของคนที่ไม่ใช่ GM** — UI-07 “ข้อมูลสรุป” แสดงผู้ขอ ผู้สร้าง ผู้รับผิดชอบ (และรายชื่อ related) แต่ `requests/{id}` มีเพียง person ID (อีเมล), `people_picker` เป็นของ GM (D-ACL-1), `people` เป็นของ server และงานลับไม่มี `request_summaries` ที่มี `assignee_label` ให้ API คืนชื่อพร้อมรายละเอียด, ให้ projection ฝังชื่อแสดงใน `requests/{id}`, หรือแสดงอีเมล?
2. **Q-S10-2 แถบ “มี X งานรอคุณยืนยัน”** — spec ไม่ระบุแหล่ง; โหลดตรงจาก Firestore ไม่ได้ (query `requests` ของคนที่ไม่ใช่ GM ถูกปฏิเสธ, `request_summaries` ไม่มีตัวตนผู้ขอและไม่มีงานลับ, `user_state` ไม่มี status) เว้นแต่ list `user_state` แล้ว get `requests` ทีละงาน — เสนอใช้ endpoint ส่วนบุคคลเดียวกับคำขอของฉัน (A06) ใช้ได้หรือไม่ หรือให้เพิ่ม status/ธงรอยืนยันใน `user_state`?
3. **Q-S10-3 ลิงก์อัปโหลดและอายุ signed URL** — Part 6 §6.10 บอก “browser upload ตรง Storage” และ “signed URL … อายุสั้น เช่น 5 นาที” สำหรับการอ่าน แต่ไม่ระบุว่าอัปโหลดใช้ signed URL แบบ PUT หรือ resumable session ที่ server เริ่ม และ 5 นาทีเป็นค่าที่ใช้จริงหรือแค่ตัวอย่าง — ควรตอบก่อน S12/A15
4. **Q-S10-4 Rules บังคับ limit ของ query หรือไม่** — ตอนนี้ query ของหน้าจอแบ่งหน้าเอง (25 รายการ) และ Rules ตรวจแค่สิทธิ์; จะให้ Rules ปฏิเสธ list ที่ไม่มี `limit` หรือ limit เกินค่าหนึ่ง (เช่น 50) ด้วยหรือไม่ spec ไม่ระบุตัวเลข

## Risk ที่ยังค้าง

- Rules รับเฉพาะอีเมลตัวพิมพ์เล็ก (`[a-z0-9._%+-]`) ตามรูปแบบ `person_id` (D-S08-4) — ถ้า Google ส่ง email claim ที่มีตัวพิมพ์ใหญ่สำหรับบัญชี Workspace บางบัญชี คนนั้นจะถูกปฏิเสธ (ปิดไว้ก่อน ไม่เปิดเกิน) ตรวจกับบัญชีจริงตอน A09 บน dev
- `firebase.sign_in_provider` และรูปแบบ token ทดสอบบน emulator เท่านั้น ยังไม่ได้ deploy Rules (task นี้ห้าม deploy)
- ค่าใช้จ่าย: ทุกการอ่าน/ query ของ client มี dependency read `access/{uid}` 1 ครั้ง (ไม่ใช่ต่อ document ในผล query) ต้องรวมในงบตาม Part 6 [S05]
- คำสั่ง `watch` ยังไม่เขียน `user_state` ของ watcher ([FU-08](../FOLLOW-UPS.md)) และ `markConfidential` ยังไม่ต่อกับ API/projection ([FU-09](../FOLLOW-UPS.md))
