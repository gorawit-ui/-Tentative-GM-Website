## สิ่งที่ส่งมอบ

| ฟังก์ชัน (`@gm/time`) | ความหมาย |
|---|---|
| `businessDuration(start, end, calendar)` | มิลลิวินาทีทางธุรกิจระหว่างสอง instant นับเฉพาะเวลาบนวันที่เปิด 24 ชม./วัน คืนค่า raw ไม่ปัด |
| `addBusinessDuration(start, duration, calendar)` | instant แรกที่สะสมครบ `duration`; เริ่มบนวันปิดจะเริ่มนับ 00:00 ของวันเปิดถัดไป; ครบพอดีสิ้นวันเปิดคืน 00:00 ของวันถัดไป |
| `addDuration(start, amount, unit, calendar)` | หน่วยตาม C8: `business_days` หรือ `continuous_24h` (นับทุกชั่วโมงรวมเสาร์-อาทิตย์/วันหยุด) |
| `CalendarSnapshot` | `{ timeZone, openWeekdays (ISO 1–7), holidays ('YYYY-MM-DD' ค.ศ.) }` |
| `BUSINESS_DAY_MS`, `HOUR_MS` | 1 วันทำการ = 24 ชม. |

Instant ทุกตัวเป็น UTC epoch milliseconds (จำนวนเต็ม) ขอบวันที่คำนวณด้วย `Intl` ตาม `timeZone` ของ snapshot ไม่ใช้ timezone เครื่อง ข้อมูลผิดรูปแบบ (duration ≤ 0, end ก่อน start, timezone ไม่รู้จัก, weekday ผิด/ซ้ำ/ว่าง, วันหยุดไม่ใช่วันจริง) โยน `RangeError` แทนการเดา

## คำถามค้าง (ไม่เดา — ต้องตอบก่อนงานที่พึ่ง)

1. **Schema ของ calendar snapshot** — Part 6 §6.7 บอกเพียง “timezone/weekday mask/holidays พร้อม hash/source reference” ไม่มีชื่อ field หรือรูปแบบ mask ผมใช้ `timeZone`, `openWeekdays` (ISO 1–7), `holidays` ใน `@gm/time` ชื่อ field ที่เก็บใน Firestore และ hash/source ให้ S04/B01 กำหนด — ยืนยันได้ไหมว่าใช้ชื่อนี้ หรือมีรูปแบบที่ต้องตรงกับ Admin UI
2. **ชื่อหน่วย** — C8/PRD เขียน `business_days` แต่ Part 6 §6.7/§6.8 เขียน `business_day` ผมใช้ `business_days` ตามลำดับความสำคัญใน INDEX (C1–C11 เหนือ Part 6) ต้องยืนยันค่าที่จะเก็บจริงใน `sla_snapshot.unit`
3. **duration = 0** — TEST-CHECKLIST §1 เขียน “zero/negative invalid input” จึงโยน `RangeError` เมื่อบวก 0 ถ้าต้องการให้ 0 คืนเวลาเริ่ม (เช่น Admin ตั้ง SLA 0) ต้องแจ้ง
4. **เศษวัน/หน่วยชั่วโมง** — PRD ให้ Admin เลือก duration/unit ของ SLA ซ่อมทั่วไป `addDuration` รับเศษวันได้ถ้าได้ผลเป็นมิลลิวินาทีเต็ม แต่ไม่มีหน่วยชั่วโมง (C8 มีแค่สองหน่วย) ต้องการหน่วยชั่วโมงหรือไม่
5. **โซนที่มี daylight saving** — นิยาม “24 ชม.ต่อวันเปิด” ตรงกับ Asia/Bangkok ซึ่งไม่มี DST โค้ดนับตามความยาวจริงของวันที่ในโซน (โซน DST อาจได้ 23/25 ชม.) ยืนยันได้ไหมว่าทุกปฏิทิน (บริษัท + 5 สถานที่) ใช้ Asia/Bangkok
6. **วันหยุดที่เป็น พ.ศ. โดยผิดพลาด** — เช่น `2569-12-31` เป็นวันที่ถูกรูปแบบจึงผ่าน validation แต่จะไม่ตรงวันใดในการใช้งาน ควรกันที่ `@gm/time` (ช่วงปีที่ยอมรับ) หรือที่ Admin/import (A11/B20) — ยังไม่ได้กันเพราะ spec ไม่ระบุช่วงปี
