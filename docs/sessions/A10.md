## ส่วนที่ 2 — A10

### ข้อมูล (server เขียนเท่านั้น; Rules ไม่เปลี่ยนสำหรับ `people`/`access`)

| เอกสาร | field | หมายเหตุ |
|---|---|---|
| `people/{person_id}` | `email`, `name`, `team_label?` (ค่าเดียว FU-10), `slack_user_id?`, `role`, `active`, `uid?`, `linked_at?`, `last_import_id?` | แหล่งข้อมูลหลักของ role/สถานะ (D-A09-1); `person_id` = อีเมลตัวพิมพ์เล็ก (D-S08-4) |
| `people_picker/{person_id}` | `name`, `team_label?` | เฉพาะคนที่ active (เดิม); เขียนพร้อม `people` |
| `access/{uid}` | `person_id`, `role`, `enabled` | **มาจาก `people` เท่านั้น** ในคำสั่งเดียวกับการแก้ role / ปิดบัญชี / ผูกบัญชี |
| `unlisted_logins/{email}` | `email`, `uid`, `first_seen_at`, `last_seen_at`, `count` | คน login ที่ไม่อยู่ในรายชื่อ — Rules ปฏิเสธทุก role (ACL matrix แถว `unlisted_logins`), อ่านผ่าน API ของ GM Admin |
| `settings/people_import` | `latest_import_id`, `imported_at`, `counts` | จำนวนเท่านั้น ไม่มีแถว |
| `scheduled_work/display_refresh-{import_id}` | `kind`, `state`, `person_ids` | FU-11 งานของ worker |

### API (GM Admin เท่านั้น — 403 `GM_ADMIN_ONLY` สำหรับ role อื่น)

- `GET /api/admin/people?q=&offset=` — หน้าละ 50 เรียงชื่อ (ไทย) ค้นชื่อ/อีเมล; คืน `role`, `active`, `linked` (เคย login), `slack_mapped` (**ไม่ส่ง Slack ID**), `in_latest_import`
- `GET /api/admin/unlisted-logins` — อีเมล + เวลาแรก/ล่าสุด + จำนวนครั้ง (มีเพดาน)
- `POST /api/admin/people/preview` `{rows, slack_column}` — ไม่เขียนอะไร: แต่ละแถว `new` / `update` (+ อะไรเปลี่ยน) / `same` / `error` (+ รหัส) และจำนวนคนที่ไม่อยู่ในไฟล์
- `POST /api/admin/people/import` `{import_id (UUID), rows, slack_column}` — body ≤ 1 MiB, ≤ 3,000 แถว; **รับเฉพาะแถวที่ map แล้ว** (field อื่น/ไฟล์ดิบ → 400); ตรวจซ้ำด้วย `checkPeopleRows` ชุดเดียวกับหน้า preview; transaction ละ 100 คน; idempotent ด้วย `commands/{import_id}` + fingerprint (ส่งซ้ำ → ผลเดิม, แถวอื่น → 409); **ไม่เก็บแถวหรือไฟล์** (`commands/{id}` เก็บแค่จำนวน)
  - คนใหม่ → `role: requester`, `active: true` (Admin ตั้ง role เอง); เคย login ก่อนอยู่ในรายชื่อ → สร้าง `access` ทันทีและลบออกจาก `unlisted_logins`
  - คนเดิม → อัปเดตชื่อ; ทีมเปลี่ยนเฉพาะเมื่อเลือกคอลัมน์ทีม; Slack ID เปลี่ยนเฉพาะเมื่อเลือกคอลัมน์ Slack (เลือกแล้วช่องว่าง = ล้าง → ส่งทางอีเมล); **role / บัญชีไม่เปลี่ยน**
  - คนที่ไม่อยู่ในไฟล์ → **ไม่ถูกปิดบัญชี** แค่ `in_latest_import: false` → ป้าย “ไม่อยู่ในไฟล์ล่าสุด”
  - ชื่อ/ทีมเปลี่ยน → `scheduled_work/display_refresh-{id}` (FU-11)
- คำสั่ง Admin (`POST /api/admin/commands`): `set_person_role` {person_id, role ∈ requester / viewer / gm_staff / gm_admin}, `set_person_active` {person_id, active}, `add_person` {email, name, team?} — ตรวจ `@gm/domain` `planPersonRole` / `planPersonActive`: **GM Admin ที่ active คนสุดท้ายเอาออกหรือปิดบัญชีไม่ได้** (409 `LAST_GM_ADMIN`, รวมถึงทำกับตัวเอง); `access/{uid}` อัปเดตใน transaction เดียวกัน → คำขอถัดไปทั้ง API และ Rules เห็นผล
- `POST /api/me/link` (login ครั้งแรก, D-A09-1/FU-38): token ต้องเป็น Google `@tdfb.co` ที่ verified (`verifyCompanySignIn` ชุดเดียวกับ authenticate) → จับคู่ด้วย**อีเมล**เท่านั้น: อยู่ในรายชื่อและ active → สร้าง `access/{uid}` จาก `people` + บันทึก `uid`; อยู่แต่ถูกปิด → ไม่มี access (หน้า “บัญชีถูกปิด”); ไม่อยู่ → บันทึกใน `unlisted_logins`; Google account ใหม่ของอีเมลเดิม → account เก่า `enabled: false`
- log มีแค่ route / status / code — ไม่มีอีเมลหรือชื่อ (emulator test ตรวจ log จริง)

### Worker (FU-11)

`display_refresh` job: อ่านงานที่ยังไม่ปิด (`queued`, `in_progress`, `waiting`, `completed` ที่รอยืนยัน) ทีละ 50 สูงสุด 4 หน้าต่อรอบ (cursor ใน job, รอบถัดไป +60 วินาที) → `refreshRequestNames` สร้าง projection ใหม่จาก people directory และเขียนเฉพาะที่เปลี่ยน; งานปิด/ยกเลิกคงชื่อเดิม; idempotent

### หน้าจอ

- **รายชื่อพนักงานและสิทธิ์** `/admin/users` (แทน placeholder ของ A09): “คนที่เข้าสู่ระบบแต่ไม่อยู่ในรายชื่อ” (เฉพาะ GM Admin, แสดงเมื่อมี) + “เพิ่มเข้ารายชื่อ” → ชื่อที่แสดง / ทีม → “เพิ่ม” (คนที่ค้างหน้า “ยังไม่เปิดใช้งาน” เข้าใช้ได้ทันทีโดยไม่ login ใหม่ ผ่าน listener `access/{uid}` เดิม); ค้นชื่อหรืออีเมล; ต่อคน: ชื่อ อีเมล ทีม (ไม่มี → “ไม่ระบุทีม”), role เป็นคำ, “Slack จับคู่แล้ว” / “ยังไม่จับคู่ Slack (ส่งทางอีเมล)”, “เข้าสู่ระบบแล้ว” / “ยังไม่เคยเข้าสู่ระบบ”, บัญชี “ใช้งาน” / “ปิดบัญชีแล้ว”, ป้าย “ไม่อยู่ในไฟล์ล่าสุด” (เมื่อเคย import); “เปลี่ยนสิทธิ์” → เลือก “สิทธิ์ใหม่” → “บันทึกสิทธิ์” → หน้าต่างยืนยัน “เปลี่ยนสิทธิ์?” บอกชื่อ อีเมล จาก…เป็น…; “ปิดบัญชี” / “เปิดบัญชี” → หน้าต่างยืนยัน; ผิด → role=alert (เช่น GM Admin คนสุดท้าย); “ดูเพิ่ม” ทีละ 50; มือถือการ์ด / desktop ตาราง (แสดงแบบเดียว)
- **นำเข้ารายชื่อจาก CSV** `/admin/users/import`: 1) เลือกไฟล์ (อ่านในเบราว์เซอร์ ≤ 2 MB / 3,000 แถว, UTF-8 + BOM, RFC 4180) 2) เลือกคอลัมน์จาก header: อีเมล, ชื่อที่แสดง, ทีม (ไม่บังคับ), Slack ID (ไม่บังคับ) — เลือกซ้ำได้รับคำเตือน 3) “ตรวจรายการก่อนบันทึก” → ใหม่ / อัปเดต / เหมือนเดิม / ผิด / ไม่อยู่ในไฟล์ + รายการแถวที่ผิดพร้อมเหตุผล (“ไม่ใช่อีเมล @tdfb.co”, “อีเมลซ้ำในไฟล์”, “ไม่มีชื่อ”, “ไม่มีอีเมล”, ยาวเกิน, Slack ID ผิดรูปแบบ) + คนที่จะเพิ่ม/อัปเดต 4) “บันทึก N รายการ” → “นำเข้าแล้ว: เพิ่ม … อัปเดต … เหมือนเดิม …” แล้วล้างไฟล์และแถวออกจากหน้า; **ส่งเฉพาะคอลัมน์ที่เลือก** (e2e ดักทุก request ว่าไม่มีคอลัมน์อื่น)

## คำถามค้าง (ไม่เดา — ทำตามที่ระบุไว้ก่อน รอยืนยัน)

1. **Q-A10-1 role กับ `settings/routing`** — การตั้ง role เป็น GM Staff / GM Admin **ไม่**เพิ่มหรือเอาคนออกจาก `settings/routing.gm_person_ids` และ default owner ของแต่ละประเภทงาน (A01 ใช้ค่านี้มอบหมายงาน) ทำให้คนที่ถูกลดเป็นพนักงานอาจยังเป็นเจ้าของงานเริ่มต้น — ให้ sync อัตโนมัติ (และกันการลด role ของ default owner) หรือให้ Admin แก้ในหน้าตั้งค่า routing (A23)
2. **Q-A10-2 ปิดบัญชีคนที่ยังถืองานเปิด** — ตอนนี้ปิดได้ทันที งานที่เป็นผู้รับผิดชอบยังอยู่กับคนนั้น — ต้องเตือน/บังคับโอนงานก่อนปิดไหม
3. **Q-A10-3 ไฟล์ export จริง** — รับเฉพาะ CSV UTF-8 (มี/ไม่มี BOM) ถ้าไฟล์จาก Workspace/Excel เป็น UTF-16 หรือ TIS-620 ภาษาไทยจะเพี้ยน — ขอไฟล์ตัวอย่าง (ข้อมูลปลอม) จาก P7-ADMIN-01 เพื่อยืนยัน encoding และชื่อคอลัมน์ทีม
4. **Q-A10-4 งาน `completed` (รอผู้ขอยืนยัน)** — FU-11 นับเป็น “ยังเปิด” จึงอัปเดตชื่อด้วย — ยืนยัน
5. **Q-A10-5 เพิ่มคนด้วยมือ** — หน้าเว็บเพิ่มได้เฉพาะจากรายการคนที่ login แล้ว (API `add_person` รับอีเมลใดก็ได้ @tdfb.co) — ต้องการฟอร์ม “เพิ่มคน” ที่กรอกอีเมลเองไหม หรือให้เพิ่มผ่าน CSV เท่านั้น
6. **Q-A10-6 แก้ชื่อ/ทีมรายคนในหน้า** — ตอนนี้แก้ได้ผ่าน CSV เท่านั้น (ตาม P7-ADMIN-01) — ต้องการแก้รายคนในหน้ารายชื่อไหม

## Risk ที่ยังค้าง

- ยังไม่เห็นไฟล์จริง (P7-ADMIN-01) — ป้องกันด้วยการเลือกคอลัมน์เอง + preview ก่อนบันทึก; ถ้ารายชื่อจริงเกิน 3,000 คนต้องแบ่งไฟล์
- `GET /api/admin/people` อ่าน `people` ทั้งหมด (เพดาน 5,000) ต่อการเปิดหน้าเพื่อค้น/เรียงในหน่วยความจำ — พอสำหรับขนาดบริษัท ถ้าโตมากต้องทำ index ค้น
- `unlisted_logins` ไม่มีวันหมดอายุ (มีเพดานการอ่าน) — ใครก็ได้ที่มีบัญชี @tdfb.co login แล้วเพิ่มแถวได้ทีละ 1 อีเมล
- คนที่ import ก่อน login แล้วถูกปิดบัญชีจะเห็นหน้า “บัญชีถูกปิด” ตั้งแต่ login แรก (ตาม linkDecision)
