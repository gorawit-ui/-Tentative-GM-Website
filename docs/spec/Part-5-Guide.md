# Part 5 — Interactive prototype

ฉบับแก้ F1–F6: รายการเปลี่ยนแปลงอยู่ใน GM-One-Stop-Service-Part-5-Patch.md

เปิด `GM-One-Stop-Service-Part-5-Prototype.html` ใน Chrome หรือ Edge ได้โดยตรง เป็น HTML ไฟล์เดียว มีฟอนต์และข้อมูลตัวอย่างอยู่ในตัว ไม่ต้องติดตั้งหรือเชื่อมอินเทอร์เน็ต

## เริ่มลอง

หน้าเริ่มต้นเป็นพนักงาน WH300 กด **แผงเดโม** มุมขวาบนเพื่อสลับมุมมองหรือจำลองเหตุการณ์ แล้วกดปิดเพื่อกลับไปใช้งานหน้าจอจริง แผงนี้แยกด้วยเส้นประและข้อความ “เครื่องมือสาธิต · แยกจาก UI จริง”

ทุกหน้าติดป้าย **ข้อมูลจำลอง** วันเริ่มต้นของเดโมคือ 28 ธันวาคม 2569 เวลา 09:30 น. ตามเวลาไทย ปฏิทินตัวอย่างเปิดจันทร์–ศุกร์และหยุด 31 ธันวาคม 2569 / 1 มกราคม 2570 ข้อมูลครอบคลุม WH300, FAC16, FAC17, Office 195 และ Cafe 222

| มุมมองในแผงเดโม | ใช้ลอง |
|---|---|
| พนักงาน · WH300 (เมย์) | แจ้งซ่อม ติดตามงานซ้ำ คำขอของฉัน และยืนยันงาน |
| GM · Sirirat / Napat / Gorawit | รับเรื่อง เปลี่ยนสถานะ ติดตาม สร้างงาน และตั้งสถานะตัวเอง |
| GM Admin | ดูงานในสิทธิ์ GM Admin; prototype ยังไม่มีหน้าตั้งค่า Admin เต็มชุด |
| Viewer | บอร์ดสรุปและ Dashboard โดยไม่มีรายละเอียดงานลับ |
| ฝ่ายที่ถูกรอ · ทีมบัญชี (นิดา) | เปิดงานที่ได้รับสิทธิ์และกด “ฝั่งฉันเรียบร้อยแล้ว” |

กด **เริ่มเดโมใหม่** ก่อนลองแต่ละ flow เพื่อกลับข้อมูลตั้งต้น การรีเฟรชหน้าเว็บเริ่มข้อมูลใหม่เช่นกัน

## Flow 1 — QR → เจองานซ้ำ → ติดตาม

1. เลือกมุมมองพนักงาน WH300 และกด **เปิด QR · WH300 ห้องแพ็ค** ในแผงเดโม สถานที่และบริเวณจะถูกเลือกให้แล้ว
2. เลือกอาการ **แอร์** แล้วกดถัดไป จะพบหน้าคั่น “มีคนแจ้งเรื่องนี้แล้ว” ของ **GM-0427**
3. กด **ใช่ เรื่องเดียวกัน — ติดตามเรื่องนี้** เพิ่มหมายเหตุหรือรูปได้หนึ่งครั้ง แล้วกดยืนยัน
4. เปิดงานจากหน้าสำเร็จ หรือไป **คำขอของฉัน → เกี่ยวข้องกับฉัน** ผู้ติดตามเห็นข้อมูลสรุป ไม่มีคอมเมนต์ รูป หรือ history ของผู้แจ้งคนแรก
5. ทำซ้ำด้วยคนเดิม จำนวนผู้แจ้งเพิ่มจะไม่เพิ่ม และไม่มี Request ใหม่ ผู้ขอเดิมยังเป็นผู้ยืนยันคนเดียว

ตัวเลือก **ไม่ใช่ แจ้งเรื่องใหม่** ไปขั้นรายละเอียดตามปกติ อาการ “อื่นๆ” ไม่จับคู่ซ้ำ ชื่อแจ้งซ่อมสร้างอัตโนมัติจากอาการ/บริเวณ/สถานที่ ข้อความที่พิมพ์อยู่ในรายละเอียดเท่านั้น

ปุ่ม QR เป็นการจำลองเข้าจาก QR ของจุดหน้างาน ไม่ใช่เครื่องสแกนกล้องหรือ QR ที่เผยแพร่ใช้งานจริง

## Flow 2 — GM รับเรื่อง → รอผู้อื่น → ฝ่ายตอบ → ทำต่อ → เสร็จ → ผู้ขอยืนยัน

1. เริ่มเดโมใหม่ เลือก **GM · Sirirat** ไปบอร์ด งาน **GM-0428** กด **รับเรื่อง**
2. กด **รอผู้อื่น** ช่องเริ่มว่าง ให้เลือก **ทีมภายใน** ใส่ชื่อ “ทีมบัญชี” เลือกนิดาเป็นผู้ติดต่อ เปิดการแจ้งเตือนแล้วบันทึก
3. สลับเป็น **ฝ่ายที่ถูกรอ · ทีมบัญชี** เปิด GM-0428 ในแท็บเกี่ยวข้องกับฉัน หรือเปิดจากหน้ารายละเอียดที่ค้างไว้ กด **ฝั่งฉันเรียบร้อยแล้ว** พร้อมหมายเหตุได้
4. งานยังอยู่ “รอผู้อื่น” แต่ขึ้นป้าย “ฝ่ายที่รอตอบกลับแล้ว” เหตุการณ์นี้ไม่เปลี่ยน `last_updated_at` เวลารอและช่วงพัก SLA สิ้นสุดที่ `responded_at`
5. สลับกลับ Sirirat กดกลับมาทำต่อ แล้ว **เสร็จ → ยืนยันเสร็จ**
6. สลับเป็นพนักงาน WH300 เปิด GM-0428 แล้วกดยืนยัน งานจะปิดทันที หากไม่ตอบ ระบบจำลองปิดเมื่อครบ 3 วันทำการตามปฏิทินบริษัท

ใช้ **ข้ามไป 4 วันทำการ** เพื่อลองการปิดอัตโนมัติ การแจ้งฝ่ายที่รอและแจ้งสถานะถูกบันทึกเป็นข้อความจำลองในแผงเดโม เมย์ไม่มี Slack ในข้อมูลตัวอย่าง จึงใช้ email @tdfb.co แทน

## Flow 3 — GM สร้าง gm_task ข้ามทีม

1. เลือก GM คนใดคนหนึ่ง แล้วเปิดฟอร์มเริ่มงานของ GM
2. ใส่ชื่อกลางๆ เลือกหนึ่งใน 7 หมวด สถานที่ไม่บังคับ เลือกผู้เกี่ยวข้องรายบุคคล
3. เลือกสถานะเริ่มต้น **รอผู้อื่น** ระบุฝ่ายที่รอและผู้ติดต่อ แล้วสร้างงาน
4. งานขึ้นบอร์ดทันที เป็น `type = gm_task`, `origin = gm_initiated`, มี `created_by_id` และไม่มี `requester_id` เมื่อ GM กดเสร็จ งานปิดทันที

ปุ่ม **เปิดแทนผู้ขอ** ใช้ฟอร์มแจ้งซ่อมเดิม เลือกผู้ขอจริงได้ หรือเลือก “ไม่พบในรายชื่อ — บันทึกชื่อข้อความ” กรณีหลังไม่มีขั้นยืนยัน และขึ้นป้าย “ผู้ขอยังไม่ได้รับแจ้ง” ให้ GM เห็น

## Flow 4 — งานลับ

1. เริ่มเดโมใหม่ ดูบอร์ดในมุมมองพนักงานหรือ Viewer จะเห็น **งานภายใน 2 รายการ** โดยไม่มีชื่องานลับ
2. งานที่ Gorawit ปักหมุดบนหน้าแรกแสดงเป็น **งานภายใน** สำหรับผู้ไม่มีสิทธิ์
3. สลับเป็น GM แล้วสร้างงานลักษณะ “เรื่องสัญญา” หรือ “เรื่องบุคคล” ธงลับเปิดเป็นค่าเริ่มต้น
4. หากแจ้งฝ่ายภายในให้มาช่วยงานลับ ต้องติ๊กยืนยันการให้สิทธิ์แยก ข้อความแจ้งจำลองแสดงเฉพาะเลขงานและ “งานภายในมีอัปเดต”

## เหตุการณ์อื่นในแผงเดโม

| ปุ่ม | สิ่งที่เปลี่ยน |
|---|---|
| มีงานใหม่เข้า | สร้างงานแจ้งซ่อมใหม่ แสดงบนบอร์ดและบันทึกแจ้งผู้รับผิดชอบ |
| ฝ่ายที่รอกดเรียบร้อยแล้ว | ตอบช่วงรอปัจจุบันที่มีผู้รับแจ้งภายใน และแจ้ง GM |
| FAC16 อินเทอร์เน็ตล่ม · เพิ่มผู้แจ้ง 1 คน | เพิ่มผู้ติดตามคนใหม่ทีละคนในงานเดียว ไม่สร้างงานซ้ำ |
| Sirirat ลา · สร้างงานใหม่ | ตั้งวันสิ้นสุดการลา สร้างงาน “ยังไม่มอบหมาย” และแจ้ง GM ทั้งสามคน |
| ข้ามไป 4 วันทำการ | ประมวลผล stale, auto-close และรีเซ็ต presence ทั่วไป; “ลา” คงอยู่ถึงวันสิ้นสุด |
| รูปถัดไปแนบไม่สำเร็จ | เลือกรูปถัดไปเพื่อทดสอบส่งงานแบบรูปไม่ครบ แล้วลองแนบซ้ำในงานเดิม |

GM เห็นป้าย “ไม่ขยับ X วันทำการ · ถึงเวลาติดตาม” และเส้นขอบ พนักงาน/Viewer เห็นข้อความกลาง “อัปเดตล่าสุด X วันทำการที่แล้ว” การปักงานเป็น “กำลังทำตอนนี้” ไม่รีเซ็ต stale

## หน้าจอและขอบเขตที่ทำไว้

- หน้าแรก: ทางลัด แถบรอยืนยัน งานปัจจุบันและสถานะทีม GM บอร์ดย่อ
- คำขอของฉัน: งานที่ขอ / เกี่ยวข้องกับฉัน จุดอัปเดตใหม่ รายละเอียด คอมเมนต์ history และรูปตามสิทธิ์ที่จำลอง
- บอร์ด: 5 สถานะ มือถือใช้ chip ทั้งหมด/ของฉัน/ยังไม่มอบหมาย และปุ่มตัวกรองเปิด sheet; ตัวกรองที่ใช้อยู่กดลบได้ Desktop ใช้ตัวกรองเดิมและลากการ์ดได้
- การ์ดรวมผู้รับผิดชอบกับเวลาอัปเดตในบรรทัดเดียว ตัดแถวสถานที่ที่ซ้ำกับชื่อ เวลาแสดงปัดลงเป็นจำนวนเต็ม
- ฟอร์มแจ้งซ่อมบนมือถือซ่อน bottom nav ใช้ action bar 64px + safe area และปุ่มถ่ายรูป / เลือกรูปภาษาไทย
- ปุ่มย้อนกลับในรายละเอียดคืนหน้าที่เปิดเข้ามา พร้อมตำแหน่งเลื่อนเดิม
- ต่ำกว่า 1536px: เสร็จ/ยกเลิกย่อเป็นแถบ กดเปิดรายการใน dialog พร้อมจำนวนรอยืนยัน ตั้งแต่ 1536px แสดงครบ 5 คอลัมน์
- งานปิด/ยกเลิกเกิน 7 วันอยู่ใน “ดูทั้งหมด” แบบแบ่งหน้า งาน completed ที่ยังรอยืนยันแสดงเสมอ
- Dashboard ด่าน B: สถานะ ภาระงาน รายสถานที่ ฝ่ายที่ถูกรอ แนวโน้มรายสัปดาห์ Scorecard และดาวน์โหลด CSV จากข้อมูลจำลอง
- การค้นหาใช้เลขงาน/ชื่อสรุป งาน Scorecard อีก 3 ตัวแสดง “ยังไม่เชื่อมข้อมูล”; URL ชีทจริงยังไม่ได้รับ จึงไม่มีลิงก์ปลอม
- หน้าติดต่อทีม GM และ FAQ: เนื้อหาตัวอย่าง ช่องทางจริงที่ยังไม่มีระบุว่ายังไม่ตั้งค่า

ฟังก์ชันที่ทำงานจริงภายในไฟล์คือการเปลี่ยนข้อมูลจำลอง แสดงหน้าจอตามมุมมอง คำนวณเวลาตัวอย่าง ย่อรูป และส่งออก CSV การส่งข้อความ/การแนบรูปขึ้น server/การเข้าสู่ระบบเป็นการจำลอง ไม่มี backend หรือการส่ง Slack/email จริง ระบบ Admin เต็มชุด, PWA, Trello และทะเบียน Phase 2 ยังไม่อยู่ใน prototype นี้

ข้อมูลทั้งหมดฝังในไฟล์เพื่อทดลอง UI การสลับ role ไม่ใช่ security boundary ของระบบจริง Part 6 ต้องออกแบบการตรวจสิทธิ์ที่ server และแยก `request_summaries` / `requests` ตามข้อกำหนดเดิม

## ไฟล์สำหรับส่งต่อทีม build

- `prototype-src/app.js`, `app.css`, `build.py`: source ของ prototype
- `prototype-src/font-*.ttf`, `OFL.txt`: ฟอนต์ IBM Plex Sans Thai Looped พร้อมใบอนุญาต
- `gm-design-tokens/`: token package ที่แก้ cascade layer แล้ว
- `prototype-qa/patch-check.cjs`: การตรวจ F1–F6, flow และ responsive ด้วย Playwright
- `GM-One-Stop-Service-Part-5-QA.md`: ผลตรวจและขอบเขตการทดสอบ

สร้าง HTML ใหม่จากโฟลเดอร์แพ็กเกจด้วย `python prototype-src/build.py` ไม่ต้องมี Node เพื่อเปิดใช้ไฟล์ที่สร้างแล้ว หากรัน QA ให้ติดตั้ง Playwright และตั้ง `GM_CHROMIUM_PATH` เป็นตำแหน่ง Chromium ในเครื่อง
