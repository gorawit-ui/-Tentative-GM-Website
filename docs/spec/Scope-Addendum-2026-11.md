# Scope Addendum — พฤศจิกายน 2569 (SC-1 ถึง SC-9)

ที่มา: ประชุมกับพี่ป๊อป (GM Admin) วันที่ 3 พ.ย. 2569 · บันทึกเมื่อ 3 พ.ย. 2569 · เอกสารนี้เป็นงานเอกสาร ไม่มีโค้ด

**ลำดับความสำคัญ:** เมื่อเรื่องเดียวกันขัดกัน เอกสารนี้ชนะ **Part 6** (รวม UI spec ต่ออายุ, §6.4.3, §6.8, §6.15) และ **Part 7** (directives + Build Plan) รวมทั้ง **R1–R5** ที่ SC-1 บอกว่ารวมและแทนที่ ส่วนที่ไม่ได้กล่าวถึงในเอกสารนี้ให้ใช้ spec เดิม; C1–C11 ยังชนะ CH-01–CH-09 เสมอ

ข้อที่เขียนว่า **(รอยืนยัน)** เป็นค่าที่เสนอ ยังไม่ใช่คำตัดสิน — อยู่ในหัวข้อ [คำถามค้าง](#คำถามค้าง-รอพี่ป๊อป) และไม่บันทึกเป็น decision ข้อที่ยืนยันแล้วบันทึกใน [DECISIONS](DECISIONS.md) เป็น `D-SC-*`

## SC-1 งานตามรอบ — ระบบเดียวใช้กับงาน 3 แบบ

| แบบ | ถึงรอบเมื่อ | หมายเหตุ |
|---|---|---|
| **ต่ออายุเอกสาร** | วันเริ่ม = วันหมดอายุ − (ยื่นได้ก่อนกี่วัน + เวลาเตรียมกี่วัน) | งานต้องแสดง “ยื่นได้ตั้งแต่วันที่ …” ให้ PIC เห็น |
| **ภาระประจำ** (รายงาน / ภาษี / โควตา) | ตามวันหรือช่วงวันในปฏิทิน | เช่น ภาษีป้ายภายในเดือนมีนาคมทุกปี, ขอโควตา 1–10 ธ.ค. |
| **แผนบำรุงรักษา (PM)** | ตามความถี่ | เช่น ล้างแอร์ทุก 3 เดือน; **(รอยืนยัน)** รอบถัดไปนับจากวันในแผน หรือจากวันที่ทำจริง |

- ข้อมูลร่วมทุกแบบ: **บริษัท** (หลายนิติบุคคล เช่น TDFB, CW, Began, Daily Happiness, Superfood, TT, Harvest Health — **รายการบริษัทตั้งค่าได้**), หมวด, ชื่อ, PIC, ลิงก์ SOP, หมายเหตุ, สถานะใช้งาน
- PM มีเพิ่ม: สถานที่, บริเวณ, ช่างประจำ
- แต่ละรอบสร้าง `gm_task` **1 งาน** (idempotent ตาม R2) มอบให้ PIC ในสถานะ **ยังไม่รับเรื่อง**
- SC-1 **รวมและแทนที่ระบบต่ออายุเดิม (R1–R5) ในส่วนที่ทับกัน**

## SC-2 การรับเรื่องและการเตือน (ใช้กับทุกแบบ)

- PIC ต้องกด **“รับเรื่อง”** — การกดรับคือหลักฐานว่าได้รับสารแล้ว
- **ก่อนรับเรื่อง:** เตือนทุกวันทำการ; ถ้าไม่รับภายใน 2 วันทำการ ให้แจ้ง GM Admin ด้วย **(รอยืนยันจำนวนวัน)**
- **รับเรื่องแล้ว:** เตือนเมื่องานไม่ขยับเกิน 3 วันทำการ ใช้กติกา stale เดิม **(รอยืนยัน)**
- **7 วันสุดท้ายก่อนกำหนด:** เตือนทุกวัน
- **เลยกำหนด:** เตือน PIC และ GM Admin ทุกวัน และขึ้นสีแดงบนหน้าแรก GM
- ใช้ระบบผลการส่งเดิม (Slack ส่งไม่ถึงให้ส่งอีเมลแทน และขึ้นป้ายเมื่อส่งไม่ถึง)
- ปิดงานต่ออายุต้องกรอกวันหมดอายุใหม่ (R3); ปิดงาน PM ต้องกรอกวันที่ทำ; แล้วรอบถัดไปเริ่มเอง
- กติกานี้แทนการเตือน 30 / 7 วันของ R4 (ดูหมายเหตุตำแหน่งข้อใน [จุดที่เปลี่ยน spec เดิม](#จุดที่เปลี่ยน-spec-เดิม) ข้อ 5)

## SC-3 นำเข้าจากชีทเดิม

CSV + เลือกคอลัมน์ + preview + เดาชนิดไฟล์ แบบเดียวกับ A10 (นำเข้ารายชื่อพนักงาน)

| ชีท / แท็บ | คอลัมน์และกติกา |
|---|---|
| ต่ออายุ — **“[New] รายการต่ออายุเอกสาร”** | บริษัท, หมวดหมู่งาน, ชื่อเอกสาร, Owner, สถานที่เก็บไฟล์, สถานะเอกสาร, วันหมดอายุ, เวลาเตรียม (วัน), ขั้นตอน/คู่มือ, ประวัติ (Log), หมายเหตุ — **Owner เป็นชื่อคน** Admin ต้องจับคู่กับรายชื่อพนักงานใน preview |
| ภาระประจำ — **“รายการส่ง report/ชำระ”** | ช่อง period เป็นข้อความ — Admin กำหนดวันเองใน preview |
| PM — **“แผนบำรุงรักษา”** | ตารางรายสัปดาห์ทั้งปี — ตัวนำเข้าเสนอความถี่และวันถัดไปจากสัปดาห์ที่มีเครื่องหมาย แล้ว Admin ยืนยันทีละรายการ |
| ช่าง — **“เบอร์ช่าง”** | ลำดับที่, ชื่อร้าน, หมวดหมู่, ที่อยู่, โทรศัพท์, LINE, FB, ผู้ติดต่อ, Link, หมายเหตุ |

ข้อมูลจริงนำเข้าผ่านหน้า Admin **หลัง deploy เท่านั้น**; ใน repo ใช้ **fixture ปลอมที่หัวคอลัมน์เหมือนจริง**

## SC-5 หน้าแรก GM แบบใหม่

ออกแบบสำหรับ **desktop ก่อน** เพราะ GM ใช้ผ่านคอมราว 80%

- **กล่องสรุป:** แจ้งซ่อมค้าง, รอผู้อื่น, ต่ออายุใกล้ถึงหรือเลยกำหนด, PM สัปดาห์นี้หรือเลยกำหนด, งานไม่ขยับหรือเกินเวลา
- **feed** ความเคลื่อนไหวล่าสุดของทุกงาน
- **ปฏิทินรายเดือน** สีแยกต่อคน แสดง PM, กำหนดต่ออายุและภาระประจำ, งานที่มีวันวางแผน และวันลา — แสดงเฉพาะทีม GM **(รอยืนยัน)**
- `gm_task` เพิ่มช่อง **`planned_date`** (ไม่บังคับ) เพื่อให้งานไปอยู่บนปฏิทินได้

## SC-6 วันลา

- ทีม GM เพิ่มหรือแก้วันลาให้กันได้
- เก็บเป็น **ช่วงวันที่** — ไม่มีช่องเหตุผลการลา ไม่ sync กับระบบ HR
- แสดงบนปฏิทิน; วันที่อยู่ในช่วงลา สถานะที่อยู่เป็น **“ลา”** อัตโนมัติ เพื่อใช้กับกติกาส่งงานของ A3

## SC-7 รายชื่อช่าง

- ใช้เลือกตอน **“รอผู้รับเหมา”** — สรุปสาธารณะยังแสดงแค่ “ผู้รับเหมา” ตาม D-S09-1
- เป็น **ช่างประจำ** ของรายการ PM

## SC-8 ผังสถานที่

รูปหรือ PDF ต่อสถานที่ GM ดูได้อย่างเดียว — ความสำคัญต่ำ **ทำท้ายสุดของด่าน B**

## คำถามค้าง (รอพี่ป๊อป)

จากการประชุม (ข้อที่ระบุ “รอยืนยัน”):

1. **Q-SC-1** แจ้ง GM Admin เมื่อ PIC ไม่กดรับเรื่องภายในกี่วันทำการ — เสนอ **2 วันทำการ**
2. **Q-SC-2** หลังรับเรื่องแล้ว เตือนเมื่องานไม่ขยับเกิน 3 วันทำการ ด้วยกติกา stale เดิม — ใช้ได้ไหม
3. **Q-SC-3** PM นับรอบถัดไปจาก **วันในแผน** หรือ **วันที่ทำจริง**
4. **Q-SC-4** ปฏิทินรายเดือนแสดง **เฉพาะทีม GM** ใช่ไหม
5. **Q-SC-5** ย้าย Trello sync, PWA, ประกาศ, ฟอร์มขอ / ส่งเอกสาร ไป Phase 2 — ยืนยันไหม (ขัดกับ C1 และ Part 7 §7.3 จนกว่าจะยืนยัน)

พบเพิ่มระหว่างเทียบ spec เดิม (ต้องการคำตอบก่อนทำ task ที่เกี่ยวข้อง):

6. **Q-SC-6** “หมวด” ของงานตามรอบ คือ 7 หมวดงาน GM เดิม (P7-UX-02) หรือหมวดใหม่ตามคอลัมน์ “หมวดหมู่งาน” ของชีท
7. **Q-SC-7** field เดิมของ R1 ที่ addendum ไม่พูดถึง (หน่วยงาน/คู่สัญญา, ที่เก็บตัวจริง, Drive link, ธงลับต่อรายการ, ประเภท 5 แบบ) ยังเก็บไหม — ชีทใหม่มี “สถานที่เก็บไฟล์” และ “สถานะเอกสาร”
8. **Q-SC-8** ค่าเริ่มต้นรายประเภทของ R1 (90/60/45/30) ยังใช้เป็นค่าเริ่มต้นของ “ยื่นได้ก่อน” หรือ “เวลาเตรียม” ไหม หรือกรอกต่อรายการเท่านั้น
9. **Q-SC-9** PIC ลาอยู่ตอนถึงรอบ: มอบให้ PIC ตามเดิม (สถานะยังไม่รับเรื่อง) หรือใช้ A3 (ยังไม่มอบหมาย + แจ้ง GM ทุกคน)
10. **Q-SC-10** ชื่องานอัตโนมัติของภาระประจำและ PM (ต่ออายุใช้ “ต่ออายุ: [ชื่อเอกสาร]” ตาม R2)
11. **Q-SC-11** “แทนการเตือน 30/7 วันของ R4” หมายถึงการเตือนใน R2 ใช่ไหม และกลุ่มรายการ “ภายใน 30 วัน / 31–90 วัน” ของ R4 ยังคงไว้
12. **Q-SC-12** “ทุกวัน” ใน 7 วันสุดท้ายและหลังเลยกำหนด นับวันปฏิทินหรือวันทำการ และการแจ้งที่ตรงวันหยุดยังเลื่อนไปเช้าวันทำการถัดไปตาม R2 ไหม
13. **Q-SC-13** ปิดงานภาระประจำต้องกรอกอะไร (เช่น วันที่ส่ง/ชำระ) และ “ไม่ทำรอบนี้” ได้ไหม
14. **Q-SC-14** “ต่ออายุและภาระประจำเห็นเฉพาะ GM” — ครอบทั้ง `gm_task` ที่สร้างจากรอบบนบอร์ดสาธารณะ (ให้เป็นงานภายใน) หรือเฉพาะทะเบียน; งานภาครัฐที่ R1 ไม่ลับยังขึ้นบอร์ดสาธารณะได้ไหม
15. **Q-SC-15** วันลาเห็นเฉพาะ GM แต่สถานะ “ลา” บนการ์ดทีม GM หน้าแรก (C7, ทุกคนเห็น) ยังแสดงไหม
16. **Q-SC-16** หน้าแรก GM ใหม่ (SC-5) แทนหน้าแรกของ GM แบบ A23 บน desktop หรือเป็นหน้าแยก; บนมือถือใช้แบบไหน
