# Part 7 — ข้อกำหนดล่าสุดจากผู้ใช้

## D1. ส่งมอบเอกสาร

Part 6 clean คืนเว้นวรรคและ backticks ชื่อ key/field/command/role ห้ามเปลี่ยนเนื้อหาหรือตัวเลข ความสะอาดของไฟล์ไม่ใช่การแก้นโยบายใหม่

`CLAUDE.md` สั้น: เป้าหมาย stack คำสั่ง build/test/deploy dev กฎ privacy/budget/CSS layer/เวลาชุด pure functions เดียว และลิงก์ spec `docs/spec/INDEX.md` ระบุเรื่องอยู่ไฟล์/หัวข้อใด; ใหม่ชนะเก่า C1–C11 ชนะ CH-01–CH-09 เสมอ `DECISIONS.md` รวม C/A/U/P/F/R/P7 ทุกข้อหนึ่งบรรทัดพร้อมต้นทาง

## D2. Milestone และลำดับงาน

สัปดาห์ 0 ก่อนโค้ด: `P7-INFRA-01`, `P7-ADMIN-01` ถึง `04` มีผู้รับผิดชอบและระบุ blocker A งานย่อยจบได้ใน Claude Code session เดียวมี acceptance test เริ่ม `packages/time` + `packages/domain` test-first เคส §6.7 แล้ว Rules + Emulator ก่อน UI

Pilot A เปิดได้แม้ Slack หรือ Gmail ช่องใดช่องหนึ่งยังไม่อนุมัติ ใช้แถบในแอปและป้าย “ผู้ขอยังไม่ได้รับแจ้ง” ถ้ายังไม่มีทั้งสองช่องต้องผ่านการทดสอบทางในแอปและ GM รับรู้ช่องทางที่ขาด ไม่ถือการอนุมัติ provider เป็น gate

## D3. Assumptions ต้องยืนยันก่อน pilot

ผู้ใช้ 100 คน / งานใหม่ 20 งานต่อวันทำการ / รายการต่ออายุ 200 รายการ / lead time ใบรับรองมาตรฐาน 30 วัน ค่านี้เป็นฐานวางแผนและงบ ยังไม่ใช่ข้อเท็จจริงบริษัท

## D4. ผู้ส่ง email

ใช้กล่องกลางของบริษัทที่มีอยู่ ไม่ผูกบัญชีพนักงานรายบุคคล ถ้ายังไม่ทราบถามพี่ทิมว่ามี mailbox กลางใดใช้ได้และส่งในนามใด Alias/Google Group ต้องมี underlying mailbox ที่ผู้ดูแลยืนยัน ห้ามเพิ่ม license เอง อนุมัติไม่ทันให้ใช้ในแอป ไม่เปลี่ยนไปบัญชีบุคคล

## D5. งาน UX ที่ค้างหลัง prototype ผ่าน

`P7-UX-01`: น้อยกว่า 1 วันทำการให้ “ไม่ถึง 1 วันทำการ” หรือ “วันนี้” ตามวันที่จริง ข้อความอัปเดตล่าสุดคง “ที่แล้ว” ค่าตัด stale ใช้จริงไม่ปัด

`P7-UX-02`: หมวดสร้างงาน GM เริ่มว่าง “เลือก...” บังคับเลือก ไม่ default “จัดซื้อทั่วไปและบิล”

Prototype F1–F6 ผู้ใช้ตรวจ Chromium ผ่าน flow/console/layout/layers/reduced motion แล้ว ไม่ต้องแก้ prototype ใหม่ เป็นหลักฐาน prototype ไม่แทน tests ระบบจริง
