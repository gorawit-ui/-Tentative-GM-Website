# Infrastructure, budget และ renewals — ข้อกำหนดจากผู้ใช้ก่อน Part 6

ไฟล์นี้บันทึกข้อกำหนดจากบทสนทนาเพื่อให้ค้นต้นทางได้; รายละเอียดเชิงเทคนิคอยู่ Part 6 ส่วนข้อยืนยันเพิ่มเติมอยู่ Part 7 ไม่มีการอนุมัติสร้างบัญชีหรือ deploy จากเอกสารนี้

## Infrastructure

ใช้ Google Cloud / Cloud Run และ Firebase ของบริษัท ดูแลโดยพี่ทิม Firebase project คือ GCP project เดียวกัน เลือก backend ให้ดูแลง่ายและเข้ากับวิธี deploy ที่พี่ทิมใช้ ซึ่งยังไม่ทราบ

ค่าเริ่มต้นที่เสนอ: project ระบบนี้ใหม่ใต้ organization/billing เดิม แยก dev/prod ไม่ใช้ project แอปเดิมที่มีข้อมูลบุคคล ใช้ custom domain ใต้ `tdfb.co` ตั้งแต่วันแรก QR ทั้ง 5 สถานที่ชี้ domain นี้ ไม่ใช้ `*.web.app`/`*.run.app` ชื่อ project/domain/region จริงยังต้องยืนยัน Firestore location เปลี่ยนภายหลังไม่ได้

Dev ทีมและ Claude Code ผ่านเครื่องทีม deploy ได้; prod ผ่านผู้ดูแล ขอ IAM ขั้นต่ำ งาน Directory/email/Slack ต้องขอผู้ดูแลแยกใน Part 7

## Budget — ข้อกำหนดบังคับ

ใช้เฉพาะ open source ฟรี, Google Cloud/Firebase บริษัท, Workspace/Slack/Trello ที่มีอยู่ ไม่เพิ่ม SaaS/แพ็กเกจรายเดือน ไม่มีบริการส่ง email/search ภายนอก, Firestore Enterprise, SaaS monitoring, paid UI/icon/motion, QR subscription, Cloud SQL, Memorystore, VPC connector หรือ `min instances` มากกว่า 0

Scheduler ฟรีนับ billing account ร่วมโครงการอื่น รวมทุกงานเป็น job เดียวทุก 15 นาที Firestore Standard ใช้ฐานข้อมูลแรกของ project ไม่เพิ่ม named database ลด Rules `get()`/`exists()` และ listener จำกัดงานเปิด + closed/`cancelled` 7 วัน เปรียบเทียบ bucket US Always Free กับใกล้ไทยพร้อมค่าใช้จ่ายตาม Part 6 Slack free ตรวจเพดาน app ก่อนสร้าง Trello labels-only ไม่ใช้ Custom Fields

Part 6 ต้องมีตัวเลขโควตาฟรีปัจจุบันและแหล่งทางการ พร้อมสมมติฐานผู้ใช้/งาน/GM 3 คนค้างบอร์ด Budget alert แค่เตือน ตั้ง 100/300/1,000 บาทต่อเดือน แยก project ส่งถึงพี่ทิมและผู้ดูแลผ่านการตั้งค่าจริงโดยผู้ดูแล Part 7 ตรวจ listener วนซ้ำ/trigger เขียนกลับตัวเอง และดู Firestore dev usage หลัง deploy ทุกครั้ง ค่าว่างระบุ assumption

## R1. รายการต่ออายุ — ด่าน B

`renewal_items`: ชื่อเอกสาร ประเภท (สัญญา / ใบอนุญาตหรือเอกสารภาครัฐ / ประกันภัย / ใบรับรองมาตรฐาน / อื่นๆ), หน่วยงาน/คู่สัญญา, สถานที่ 5 แห่งหรือทั้งบริษัท, วันหมดอายุ, จำนวนวันเริ่มล่วงหน้า, ผู้รับผิดชอบค่าเริ่มต้น Gorawit, Google Drive link, ที่เก็บตัวจริง, ธงลับ

Default lead time Admin แก้ได้และ override รายรายการ: สัญญา 90 วัน ภาครัฐ 60 วัน ประกันภัย 45 วัน อื่นๆ 30 วัน ใบรับรองมาตรฐาน 30 วันเป็น assumption ต้องยืนยัน สัญญาลับค่าเริ่มต้น ภาครัฐไม่ลับค่าเริ่มต้น

## R2. สร้างงานและเตือน

ถึงวันเริ่ม สร้าง `gm_task` “ต่ออายุ: [ชื่อเอกสาร]” ผูก item หนึ่งงานต่อหนึ่งรอบ idempotent ใช้ job เดิม ห้ามเพิ่ม Scheduler job งานยังไม่ปิดเตือนเหลือ 30 และ 7 วัน หลังหมดอายุแจ้ง GM Admin + เกินกำหนด วันหมดอายุเป็นวันปฏิทิน การแจ้งที่ตรงวันหยุดส่งเช้าวันทำการถัดไป ใช้ flow รอผู้อื่นเดิม

## R3. ปิดรอบ

ปิดงานได้หลังกรอกวันหมดอายุใหม่ ลิงก์เอกสารใหม่ไม่บังคับ เลื่อนไปรอบถัดไปเอง ไม่ต่ออายุให้เลือก “ไม่ต่ออายุ” พร้อมเหตุผล แล้วเก็บรายการเข้าประวัติ

## R4. หน้าจอและ Scorecard

เฉพาะ GM: รายการเรียงตามหมดอายุ กลุ่มเกินกำหนด / ภายใน 30 วัน / 31–90 วัน / ปกติ; ฟอร์มเพิ่มและแก้ ไทล์ “สัญญา / ต่ออายุค้าง” เป็นตัวเลขจริงพร้อมนิยามนับ ทะเบียนเอกสารเต็ม/ลงทะเบียน 3 วัน/ที่เก็บและค้นทะเบียนยัง Phase 2; ฟอร์มขอ/ส่งเอกสารอย่างง่าย US-04 ยัง B ตาม C1

## R5. CSV ตั้งต้น

GM Admin นำเข้าชีท “สถานที่จัดเก็บเอกสารตัวจริง_รายการต่ออายุเอกสาร” ผ่าน CSV มี preview และรายงานแถวผิด วันที่ พ.ศ. ตรวจแปลง เช่น 2570 → 2027 ให้ยืนยันก่อนบันทึก
